# Workflow B — Competitor SERP Analysis

## Sampling and rank integrity

Start with user-supplied rivals, then discover sites competing for the actual queries. Label each as business competitor, organic search competitor, or both. A publisher, marketplace, forum, or video platform can be a search competitor without selling the same product.

Aim for 5–10 organic results per core keyword when accessible. State the number collected, inspected, blocked, and omitted; never fabricate entries to reach ten. Keep ads and special features separate from organic numbering. Preserve multiple URLs from one domain if they answer different tasks.

Record query, tool, search engine/surface, requested and observed country/language/device, observation timestamp/timezone, personalization state, and depth. A generic web-search tool's ordering is tool order only, not exact live Google ranking. In that case set `position` to N/A and describe tool order in evidence. A provider's explicitly defined rank is a provider observation with its conditions, not a universal rank.

For every accessible result record:

- Position (if established), result type, URL, domain, observed SERP title, and page title when opened; distinguish title rewrites.
- Content type and intent fit: aligned, partial, mismatched, or unknown, with reasons.
- Core content, differentiators, and what the page allows the user to do.
- Publication/update evidence and whether facts appear current; an “updated” date alone proves no substantive revision.
- Internal links, heading/navigation structure, visible conversion path, and improvement opportunities.
- Evidence IDs, opened-versus-snippet-only status, and blocked inspection limits.

## Quality comparison

Compare intent fulfillment, correctness/clarity, original information, actual experience/evidence, completeness for the task, useful visuals, usability, navigation, conversion path, and freshness. Quote only short necessary excerpts; link to sources. Assess accessibility barriers and deceptive CTA patterns as user problems, not growth tactics.

Use qualitative findings with evidence. Word count, number of headings, schema quantity, and third-party domain authority are not Google quality scores. A page having a feature while ranking well does not prove that feature caused its rank. Estimated visits, backlinks, or provider difficulty scores need provider/date/method and `[Tool Estimate]`; without data use `[Unavailable]`.

## Gap analysis

Look for an unmet user need, not merely a topic a rival mentions. Distinguish an observed omission in the inspected content from a hypothesis about what users need.

| Gap type        | Question                                                                                           |
| --------------- | -------------------------------------------------------------------------------------------------- |
| Information Gap | Which necessary answer, constraint, or decision detail is missing?                                 |
| Experience Gap  | Would genuine testing, first-hand use, or a worked example resolve uncertainty?                    |
| Feature Gap     | Is a useful calculator, filter, comparison, demo, or interactive function missing?                 |
| Format Gap      | Would a diagram, video, checklist, accessible table, or playable experience better serve the task? |
| Trust Gap       | Are authorship, methodology, sources, pricing, limitations, or ownership unclear?                  |
| Conversion Gap  | Is a useful next action missing or does the page obstruct it?                                      |

For each gap provide: finding, actual evidence, expected user problem, proposed original solution, implementation difficulty, expected business value, validation needed, and confidence. Unobserved content is not a confirmed omission. A sampled page's gap is not a domain-wide finding.
