# agent-test

macOS에서 여러 AI 에이전트의 단발 테스트를 사용자 공통 큐와 예약 예산으로 실행하는 작은 Python 도구입니다. 이 저장소는 구현을 보관할 뿐입니다. 다른 저장소의 `package.json`, lockfile, CI 또는 동료의 실행 환경을 수정하지 않습니다.

## 설치 및 실행

Python 3.10 이상과 각 프로젝트의 기존 런타임·테스트 의존성이 필요합니다. 별도 Python 패키지는 없습니다. 프로젝트 의존성이나 브라우저를 자동 다운로드하지 않습니다.

```sh
python3 tools/agent-test/install.py install
~/.local/bin/agent-test config
~/.local/bin/agent-test run -- vitest run
~/.local/bin/agent-test run -- pnpm test
~/.local/bin/agent-test run -- pnpm exec playwright test
~/.local/bin/agent-test run -- jest
~/.local/bin/agent-test run -- node --test example.test.mjs
```

명령은 대상 프로젝트 디렉터리에서 실행합니다. 로컬 도구 버전과 호출자의 환경을 사용합니다. `~/.local/bin`이 PATH에 없으면 절대 경로로 호출하세요. RTK 환경에서는 `rtk proxy ~/.local/bin/agent-test ...`를 사용합니다.

설치 위치:

- `~/.local/bin/agent-test`: 현재 Python 경로를 고정한 실행 파일
- `~/.local/share/agent-test/app/`: 사용자 전역 프로그램 복사본
- `~/.local/state/agent-test/`: 권한을 제한한 소켓, 설정, 상태, 오류 로그
- `~/.claude/settings.json`: 기존 설정을 보존하며 추가하는 Bash PreToolUse Hook

`AGENT_TEST_HOME`은 격리된 검증에 쓰는 상태 경로 재정의입니다. 일반 사용 시 설정하지 마세요. 다른 값을 쓰는 세션은 별도 예산을 사용하므로 전역 제어에서 벗어납니다.

## 지원 범위와 의미 보존

Vitest, Playwright, Jest, Node 내장 테스트 러너는 도구별 어댑터로 워커 상한을 적용합니다. 지원되는 직접 명령과 분석 가능한 단순 package 스크립트를 처리합니다. 알 수 없는 옵션, 복잡한 셸 스크립트, lifecycle 동작을 안전하게 보존할 수 없는 명령은 오류와 함께 거절합니다. 원래 테스트를 조용히 생략하지 않습니다.

```sh
agent-test run --workers 1 -- vitest run src/example.test.ts
agent-test run --runner playwright -- pnpm exec playwright test
agent-test run --runner generic -- python3 -m unittest discover
```

`generic`은 사용자가 명시적으로 선택하는 예약 경로입니다. 알려지지 않은 명령에 워커 옵션을 임의로 넣지 않으며, 전체 예산을 독점 예약합니다. **해당 명령 내부의 스레드·프로세스 개수를 제한한다는 뜻은 아닙니다.** 실행 대상과 부수 효과는 호출자가 확인해야 합니다.

단순 package 스크립트 어댑터는 패키지 매니저를 실행하지 않고 로컬 러너를 직접 실행합니다. 호출자의 환경변수는 전달하지만 패키지 매니저가 추가하는 `npm_*`, `INIT_CWD`, `node_modules/.bin` PATH는 생성하지 않습니다. 이에 의존하는 테스트나 pre/post lifecycle 스크립트는 `--runner generic -- npm test`처럼 원래 패키지 매니저를 실행하세요. 이 경우 내부 워커 제한 대신 전역 독점 예약만 적용됩니다.

Watch·UI·디버그처럼 사용자의 입력을 기다리는 장기 세션은 일반 단발 큐의 대상이 아닙니다. stdin은 DEVNULL이므로 대화형 테스트에는 사용하지 마세요.

## 구조와 정책

```text
각 레포/워크트리의 CLI
        │ Unix 소켓
사용자별 데몬 1개: FIFO, 토큰 예약, 상태 저장
        │ 작업별 제어 소켓
가디언: 독립 프로세스 그룹의 수명 소유
        │
테스트 러너 및 자식 프로세스
```

Python 표준 라이브러리는 별도 빌드나 런타임 패키지 없이 파일 잠금, Unix 소켓, 프로세스 그룹과 macOS kqueue를 사용할 수 있어 선택했습니다. Rust는 배포 바이너리 빌드가 추가되고, Node는 기존 환경에서 편리하지만 이 작은 OS 조정 작업에 외부 런타임 변경을 추가할 이유가 없었습니다.

파일 잠금만으로는 FIFO 대기, 취소와 실시간 출력을 함께 관리하기 어렵습니다. SQLite도 큐를 저장할 수 있지만 프로세스 생명주기와 출력 전달은 별도 구현이 필요합니다. 따라서 작은 이벤트 기반 단일 작성자 데몬을 사용합니다. 첫 요청이 데몬을 시작하고 파일 잠금으로 중복 기동을 막습니다. 대기 클라이언트는 소켓 이벤트를 기다리며 permit을 반복 조회하지 않습니다.

기본값은 실제 성능 코어와 논리 코어 정보를 이용해 계산합니다. M5 4P+6E에서는 초기 예산 4, 실행당 워커 2, 동시 실행 2를 사용합니다. 토큰은 예약 단위이지 CPU affinity나 OS 수준 CPU 제한이 아닙니다. 러너 메인 프로세스, 브라우저, 변환 작업과 사용자 코드의 별도 스레드는 추가 자원을 사용합니다.

- `fixed`: 요청당 설정된 워커 상한만큼 예약. 단순한 기준 정책입니다.
- `weighted`: 요청한 워커 수만큼 예약. 실행 수 상한도 함께 적용합니다.
- 엄격한 FIFO를 사용합니다. 작업별 실행·대기 시간 제한이 있으며 우선순위 추월은 없습니다.
- 같은 워크트리는 기본 직렬화하고 같은 CWD·명령의 중복 등록은 거절합니다.
- `--allow-duplicate`는 중복 등록만 허용합니다. 독립된 테스트임을 확인한 경우에만 `--concurrent-worktree`를 별도로 사용합니다.
- head-of-line blocking은 의도한 비용입니다. 짧은 작업 우선이나 프로젝트별 round-robin은 측정 없이 추가하지 않습니다.
- 부하 기반 동적 증감, QoS 튜닝, 코어 고정은 구현하지 않습니다.

## 생명주기와 안전 경계

1. 데몬은 실행 예약을 먼저 기록합니다.
2. 새 프로세스 그룹의 가디언은 실행 허가 메시지 전까지 테스트를 시작하지 않습니다.
3. 가디언 PID/PGID 기록을 저장한 뒤 실행 허가를 보냅니다.
4. 테스트 종료·취소·제어 연결 단절 시 가디언이 같은 그룹의 자식을 정리합니다.
5. 그룹이 남아 있으면 토큰을 즉시 반환하지 않고 격리합니다.
6. 재시작 후에도 같은 부팅 세션의 잔존 그룹을 확인합니다. 불확실하면 신규 실행을 막습니다.

단순 heartbeat 만료로 살아 있는 작업의 토큰을 회수하지 않습니다. 가디언이 그룹 정체성을 소유한 상태에서만 그룹 종료를 요청합니다. 복구 과정에서 과거 PID를 근거로 무관한 프로세스를 자동 종료하지 않습니다.

데몬 장애로 연결이 끊긴 요청은 자동 재실행하지 않습니다. 테스트의 외부 부수 효과가 중복될 수 있기 때문입니다. 호출자는 오류를 받은 뒤 상태를 확인하고 새로 요청해야 합니다. 대기열은 장애 후 자동 복원·재실행하지 않습니다.

제약:

- 같은 사용자 권한의 협조적 프로세스 조정기이며 보안 샌드박스가 아닙니다.
- 자식이 새 세션을 만들어 그룹을 탈출하면 완전한 정리를 보장하지 못합니다.
- 이미 실행 중인 외부 개발 서버는 스케줄러 소유가 아닙니다. 종료하거나 CPU 사용을 제한하지 않습니다.
- macOS 부모 종료 감시는 커널 이벤트를 사용하지만 모든 에이전트 실행기의 임의 계층을 완전히 식별한다고 보장하지 않습니다.
- 가디언까지 강제 종료된 그룹은 잔존 상태에 따라 운영자 확인이 필요할 수 있습니다.
- PID 재사용 여부가 불확실하면 가용성보다 과다 할당 방지를 우선합니다.

## 상태 조회와 복구

```sh
agent-test status
agent-test status --json
agent-test queue --json
agent-test cancel <job-id>
agent-test recover --json
agent-test stop
```

JSON에는 예산과 예약량, 실행·대기 작업, 프로젝트·워크트리, PID, 대기/실행 시간, 최근 결과, 평균/P95 대기 시간과 처리량이 포함됩니다. 예약은 실측 CPU 사용량과 다릅니다. 통계는 보존된 최근 기록 범위이며 daemon 재시작 전후의 통계 창을 확인해야 합니다.

격리 상태가 있으면 `status --json`으로 해당 그룹을 확인하세요. `recover`는 사라진 그룹의 예약을 정리하는 명령이지 오래된 PID를 강제 종료하는 명령이 아닙니다. 살아 있는 그룹이 남았는데 상태 파일을 지워 강제로 우회하지 마세요. 상태가 손상되면 데몬은 보수적으로 시작을 거절합니다.

환경변수·원문 명령 인수·테스트 출력은 영구 작업 기록에 저장하지 않습니다. 작업 출력은 호출자에게 전달되므로 테스트 자체가 출력하는 비밀을 자동으로 숨겨주지는 않습니다. 작업 기록은 개수와 기간을 제한합니다.

기본 기록 한도는 최근 500개·7일입니다. 이력 파일은 작업 상태 변경 시 갱신합니다. 격리된 그룹이 있을 때만 2초 간격으로 생존 여부를 확인하며 정상 대기 중에는 이 복구 조회를 하지 않습니다.

## 설정 변경과 머신 이전

```sh
# 실행·대기·격리 작업이 없을 때만 중지
agent-test stop
agent-test config --set budget=4 workers=2 max_runs=2 policy=fixed
agent-test config --json
```

설정 변경은 데몬이 정지한 상태에서 수행합니다. 잘못된 설정은 기존 설정을 덮어쓰지 않습니다. 작업 시간 제한은 `--timeout`으로 줄일 수 있지만 설정된 최대값보다 늘릴 수는 없습니다.

15/18코어 Mac의 최적값은 이 머신에서 검증할 수 없습니다. 이전 후 코어 토폴로지와 다른 상주 프로세스를 확인하고, 4토큰 기준선과 6·8토큰 후보를 동일 작업으로 비교하세요. 더 많은 코어라는 이유만으로 전체 코어 수를 테스트에 할당하지 않습니다.

## Claude Hook 및 우회 경로

설치기는 설정을 백업하고 자신이 소유한 Hook 항목만 추가·제거합니다. 기존 RTK 및 다른 Hook은 유지합니다. 명령을 경쟁적으로 수정하지 않고 직접 테스트 실행을 거절하며 유효한 대체 명령을 안내합니다.

자동 적용 범위는 `~/.local/share/agent-test/hook-scope.json`의 `roots`와 `worktrees`입니다. 기본 `roots`는 `~/orca`입니다. 그 밖에 둔 연결 워크트리는 `worktrees` 배열에 절대 경로를 추가하세요. CLI 자체는 어느 디렉터리에서도 같은 사용자 예산을 공유합니다. 설치 후 기존 Claude 세션을 재시작하고 `/hooks`에서 적용 상태를 확인하세요.

Hook은 10초 제한으로 실행합니다. 파싱 실패 시 테스트로 보이는 명령은 거절하지만, Python 실행 자체의 실패나 Hook 타임아웃은 Claude 버전과 설정에 따라 비차단 오류가 될 수 있습니다. 무한 재시도하지 말고 안내된 CLI 명령으로 전환하세요. Hook이 중단되었다면 CLI를 직접 사용하고 설치 경로와 Python을 점검하세요.

이 Hook은 모든 셸 실행을 통제하지 않습니다. 터미널 직접 실행, 다른 에이전트 도구, 동적으로 생성된 명령, 외부 스크립트의 간접 호출, Hook 비활성화 및 별도 상태 경로는 우회할 수 있습니다. 단순 package 스크립트를 검사하는 것과 임의 프로그램의 실행 내용을 완전히 분석하는 것은 다릅니다. Hook 오류·타임아웃이 항상 fail-closed로 처리된다고 가정하지 마세요.

## 검증과 벤치마크

저장소의 기본 `pnpm test`나 동료의 실행 환경에 Python 의존성을 추가하지 않았습니다. 이 도구 자체 검증은 명시적으로 실행합니다.

```sh
python3 -m unittest discover -s tools/agent-test -p 'test_*.py' -v
python3 tools/agent-test/diagnose.py --help
python3 tools/agent-test/benchmark.py --help
python3 tools/agent-test/smoke.py --help
```

실제 측정 결과 및 검증 상태는 `REPORT.ko.md`와 `results/`를 참조하세요. synthetic fixture를 실제 러너로 실행한 검증과 기존 프로젝트의 실제 테스트 묶음 성능 측정은 구분합니다. 표본 CPU/RSS 최댓값을 진짜 순간 최댓값으로 표현하지 않습니다. 단기 검증을 24시간 운영 검증으로 표현하지 않습니다.

## 제거

```sh
agent-test stop
python3 ~/.local/share/agent-test/app/install.py uninstall
```

작업이 남았으면 먼저 상태를 확인하고 필요한 작업만 취소하세요. 제거기는 자신이 추가한 Hook과 변경되지 않은 전용 launcher만 제거하고 다른 설정을 보존합니다. 프로그램 복사본·백업·작업 기록은 복구를 위해 남깁니다. 다른 변경이 생겼을 수 있으므로 예전 설정 백업 전체를 무작정 복원하지 마세요.
