# Verification

Report every check separately. A passing type check says nothing about fun.

| Check                            | Command (starter)        | Proves                                                                   |
| -------------------------------- | ------------------------ | ------------------------------------------------------------------------ |
| Types                            | `npm run typecheck`      | app compiles; `tsconfig.core.json` compiles the core without the DOM lib |
| Lint                             | the repo's existing lint | local conventions                                                        |
| FSD                              | `npm run check:fsd`      | Steiger passes on `src`, fails on the violation fixture                  |
| Headless                         | `npm test`               | rules and session behavior below                                         |
| Build                            | `npm run build`          | production bundle                                                        |
| Browser                          | `npm run test:e2e`       | real input journey below                                                 |
| Device, usability, fun, business | people                   | only when observed                                                       |

## Headless cases

- Core rules: start, success, partial success, failure, restart.
- Time: zero, negative and non-finite deltas ignored; catch-up clamp; different delta splits give the same state.
- Pause: independent reasons; a system pause (hidden, context-lost) is not user-resumable; input while paused discarded; first delta after resume discarded, and restart clears that pending discard.
- Runs: stale `runId` input ignored; restart leaves no entities, events or commands from the previous run.
- Snapshot: same reference when unchanged, new immutable value on change.
- Isolation: two sessions do not affect each other.
- Lifecycle: `dispose` is idempotent; no notifications after dispose or unsubscribe.
- Boundary: core files import only core modules and use no platform globals, ambient time or randomness.
- Write the failing test before the rule. Mutate one guard and confirm a test fails; record mutations that survive.

## Browser journey

- Real taps and clicks: start, play, fail, retry, pause and resume, hidden tab.
- Canvas visible, HUD in viewport, no horizontal overflow at 320×568 and after resize, no `console.error` or `pageerror`.
- Wait for a state (`data-status`, a role, text), never a fixed sleep. Retry loops use `expect(...).toPass()` with a bound.
- If Playwright or a WebGL-capable browser is unavailable, mark the browser check `BLOCKED` or `NOT_RUN` with the reason.

## GLB runtime checks

Applies only to GLB implementations; record `N/A: basic shapes, no GLB` otherwise. Follow the
[runtime asset contract](asset-loading.md) and the blueprint's screen/scene table. Static document tests and screenshots
do not prove runtime lazy loading. Keep the existing report schema unchanged: link separate network/parse/resource logs
from `checks.browser.evidence`, build inspection from `checks.build.evidence`, and remaining gaps from `open_risks` or the blueprint.

### Observation setup

- Start cold-cache request observation **before navigation/import** in a fresh browser context. State the HTTP/browser cache and
  service worker settings; use a genuinely cold session so previous loads cannot hide eager work. Inspect the initial
  load as well as transitions. Warm-cache re-entry is a separate test in the same context, not another cold run.
- Derive the expected URL set from actual production build output/manifest and the selected assets' dependencies, not
  just a `.glb` extension filter. Match hashed/query URLs and record external texture/buffer requests too. A self-contained
  GLB legitimately has no external dependency requests. Unselected assets must have neither requests nor parse activity.
- Inspect production JS and asset mappings for embedded GLB bytes, data URLs/base64 or generated byte arrays. URL-only
  imports are allowed. Missing network requests cannot pass this check if the binary was already inlined into initial JS.
  Run the built application, not only a development server; dynamic import/code chunks and GLB loading are separate evidence.
- For cold-network tests block service workers or explicitly clear their registrations/CacheStorage. If the target uses
  PWA/SW, also run a fresh-context test with the actual worker enabled through installation/activation and inspect its
  precache list/requests. Blocking the worker alone does not verify the deployed precache policy.
- Count real network request starts separately from parser invocations and resource disposal. Use small test-only probes
  at the actual loader/parse/dispose boundary where needed; HTTP cache hits can still hide duplicate parsing. Record the
  observation layer and asset key. Do not expose test probes as new ECS/session APIs.
- Control delayed/failing responses with explicit barriers. In the A→B race, release A after B is ready and await A's
  settlement/host processing before asserting that B is unchanged. Merely seeing B before A completes proves nothing.
  Exercise both completion orders and exit-before-completion without relying on request cancellation or fixed sleeps.

### Acceptance cases

| Case                     | Required observation                                                                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Cold home             | Only home-required GLBs/dependencies requested; a 2D home requests zero GLBs.                                                                                                     |
| 2. Before play           | No play-only GLB request or parse before committed play entry; required models gate play.                                                                                         |
| 3. Selected character    | Selecting A for the displayed scene never requests/parses B or another map; skin detail loads only the displayed skin.                                                            |
| 4. Registry import       | Import alone starts zero GLB/dependency requests and zero parses.                                                                                                                 |
| 5. Concurrent demand     | Two consumers of the same asset share one request and one parse, while distinct required assets may load in parallel.                                                             |
| 6. Warm re-entry         | Retained cached assets are reused without another fetch/parse; document the retention premise.                                                                                    |
| 7. Stale result          | A loading → B selected → late A completion does not attach to B, revive a destroyed scene or overwrite B's status.                                                                |
| 8. Failure/retry         | Error, retry and safe exit work; no required invisible actors activate. Only failed/missing current assets retry; successful assets stay reused.                                  |
| 9. Shared ownership      | One consumer leaving does not dispose resources used by another attached or pending consumer. Instance-specific mutation does not affect a sibling.                               |
| 10. Repeated transitions | After warm-up and repeated transitions, idle cache/instance/geometry/material/texture counts stay within the declared policy; final unused resources are disposed by their owner. |

For case 10 record active versus idle ownership and a baseline; renderer-internal caches may remain nonzero. Prefer
resource counts/disposal events to invented GPU byte figures. File transfer size is not GPU memory usage. Test eviction
as well as reuse: a never-evict cache can pass warm re-entry while leaking on every new selection.

If there are no suitable real assets, generate a small valid GLB fixture locally; do not download paid or unclear-license
models. This package's independent [runtime fixture](../../../scripts/fixtures/asset-loading/README.md) exercises actual
GLTFLoader behavior outside the shapes-only starter. Fixture success proves only that fixture/host, not an arbitrary game,
R3F/Next.js implementation or agent behavior. Mark unavailable runtime checks `NOT_RUN`/`BLOCKED`, never substitute a
passing document contract. Report request/transfer before-and-after figures only when actually measured under matching conditions.

## Visual review is separate from behavior checks

Follow [code visual design](code-visual-design.md) for the reference-to-code pilot and screenshot critique.
Record the visual status and evidence in the blueprint. When a compatible prototype report exists,
link it from `checks.browser.evidence` and include unresolved gaps in `open_risks`. A passing browser journey does not automatically pass visual
review; for in-scope polish, no inspected captures means `NOT_RUN` or `BLOCKED`, even if typecheck/build/E2E passed.

## Status words

`PASS` (ran, exit status and output support it) · `FAIL` (ran, failed; quote the decisive line) ·
`NOT_RUN` (not executed, including a failed dependency install) · `BLOCKED` (missing tool, permission or environment).
If dependency download failed, every later check is `NOT_RUN`. Installed-but-unverified code is delivered as files, not as "ready to run".
