# 구현 인계·실험

## 책임

Input은 gesture ID와 월드 x를 생성한다. Rules/Simulation은 유효 입력·객체·충돌·합체·점수·overflow 시간을 소유한다. Three.js는 결과를 표현한다. HUD는 낮은 빈도의 점수/다음 물체/상태를 받는다. Storage는 개인 최고점·음소거만 저장한다. 새 run은 이전 effects/listeners/timers/gesture를 정리한다.

2D 원 판정과 Three.js 표현을 매핑한다. 물리 엔진과 timestep은 구현 스파이크에서 결정하되 render frame 횟수로 점수를 계산하지 않는다. seed 하나로 모든 기기의 부동소수점 결과가 동일해진다고 가정하지 않는다.

사건 예: drop_committed(runId, gestureId, entityId), merged(runId, eventId, consumedIds, newEntityId, tier), run_ended(runId, eventId, score). 각 ID의 중복 처리와 run 일치를 검사한다. 효과는 사건을 재생할 수 있어도 점수를 다시 지급하지 않는다.

## 최소 플레이 가능한 범위

도형으로 drop→merge→score→overflow→replay와 pauseReasons를 먼저 구현한다. 실제 무광 아트보다 입력 위치와 취소를 먼저 확인하되 간단한 소리/스케일 피드백은 초기에 함께 비교한다. 서버·광고·상점은 만들지 않는다.

## 환경·성능

목표는 모바일 브라우저지만 특정 기기/OS/브라우저 버전은 테스트 전에 기록한다. 현 문서에는 실측 FPS·로딩 수치가 없다. frame-time 분포, cold-load에서 첫 유효 입력까지, 메모리 누수와 반복 재시작을 측정한다. low-effect는 그림자/파티클을 줄여도 danger와 collision cue는 유지한다.

## 실험

| ------------ | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------- |
| X-understand | 안내 없이도 release 투하와 합체 관계를 이해한다 | 5명 정도의 탐색적 세션을 계획. 시작 방법 설명 없이 최초 행동·취소·합체 설명을 관찰. 숫자는 통계적 검증 표본이 아님 | planned |

| X-feel       | 적은 합체 강조가 입력 확신을 돕되 가리지 않는다 | 같은 규칙에서 정적 강조와 squash/소리 비교. 오입력·가림·자발적 재도전을 관찰                                       | planned |

사업 실험은 별도이며 위 탐색적 세션으로 매출·리텐션 성공을 선언하지 않는다. 입력을 몰라 멈추면 온보딩/preview, 선택이 같으면 규칙, 표현이 가리면 피드백을 다시 연다.

## 이벤트·지표

first_meaningful_action은 해당 run에서 사용자 투하 객체가 처음 merge에 참여할 때 한 번. replay_start는 result에서 직접 누른 새 판만 계산하며 강제 재시작은 분리한다. 분모는 해당 결과 화면을 실제로 본 고유 세션/사용자로 구분해 기록한다. 다음 날 재방문을 측정할 때는 달력일 Asia/Seoul인지 elapsed 24h인지 사전 지정하고 관찰 창이 완료된 cohort만 사용한다.

아직 사용자·재미·매출 관찰은 없고 game code도 없다. 기획상 자체 검토와 구조 검사만 가능한 예제다.
