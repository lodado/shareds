# 도토리 정원 — 기획 예제

**합성 설계 예제이며, 출시작·실측·플레이테스트 결과가 아니다.** 게임 기획 산출물의 구체성을 보여주기 위한 제안이다. 기본 모드는 PLAN_ONLY. 다음 수치와 정책은 모두 초기 튜닝안이다.

## 한 문장

좁은 화분에 씨앗을 놓고 같은 단계끼리 합치며, 지금 안전하게 합칠지 다음 합체를 위한 공간을 남길지 결정한다.

가정: 1인 개발, 모바일 웹, 한 손, 세로, 고정 카메라. Three.js로 재질과 합체를 표현하지만 판정은 한 평면의 원으로 한다. 세계 좌표의 가로는 [-1,1], 화분 바닥 y=0, 위쪽 +y다. 깊이 이동은 없다.

목표는 개인 최고 점수. 별도 승리 조건 없는 한 판이다. 서버·로그인·상점·광고·랭킹·유료 재화는 MVP 제외. 원본 수박게임의 아트나 화면을 복제하지 않는다. 상업적 수요와 차별성은 미검증이다.

## 핵심 판단과 숙련

초보자는 당장 같은 씨앗 가까이에 떨어뜨린다. 숙련자는 큰 물체 옆의 작은 틈에 씨앗이 고립되는 상황과 다음 물체를 함께 보고 공간을 남긴다. 안전한 낮은 배치와 높은 연쇄 합체 가능성 사이에서 판단하도록 의도한다.

반례: 아무 위치에 놓아도 결과가 거의 같거나 무작위 흔들림이 점수를 지배하면 배치 판단 가설이 무너진다. 이 경우 상점을 추가하는 대신 반지름·마찰·화분 너비·다음 물체 정보부터 다시 실험한다.

## 규칙

| ID      | 초기 명세                                                                                                                                                                                    | 확인할 반례                                              |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| R-drop  | 손가락 위치로 가로 x를 미리 보고 release에서 1개 확정. x를 벽과 물체 반지름 안쪽으로 clamp. pointercancel은 생성하지 않음. 다음 투하는 300ms의 게임 시간 이후 허용                           | 같은 gesture ID의 release 두 번에도 1개만 생성           |
| R-merge | 단계 1~3의 같은 단계가 접촉하면 2개를 소모하고 다음 단계 1개 생성. 단계 4는 더 합쳐지지 않음. 한 tick의 pair는 entity ID 정렬 순서로 처리, 소모 ID는 즉시 제외, 새 객체는 다음 tick부터 합체 | 같은 객체가 두 pair에 들어 있어도 한 번만 소모           |
| R-score | 합체로 생성된 단계 2/3/4에 2/4/8점. merge event ID당 한 번. 낙하·효과·재조회로 가산하지 않음                                                                                                 | 효과가 재생돼도 점수 유지                                |
| R-end   | preview 제외 실제 객체의 상단 y+r가 2.2를 연속 1.5초 넘으면 종료. 각 객체 생성 후 0.8초는 overflow 판정 제외. 아래로 내려오면 해당 타이머 reset. 게임 시간 정지 중 타이머도 정지             | 잠깐 통과하는 낙하와 정지된 탭이 즉시 패배를 만들지 않음 |
| R-reset | 새 run ID, 점수 0, 새 seeded sequence, 진행 객체/gesture/timer 전부 초기화. 음소거와 개인 최고점만 유지                                                                                      | 이전 run의 늦은 사건이 새 판을 변경하지 않음             |

단계별 반지름은 0.10/0.15/0.225/0.34로 제안한다. 첫 3개는 단계 1, 이후 생성은 단계 1:80%, 단계 2:20%의 튜닝 가정이며 다음 1개를 공개한다. seeded RNG는 재현을 돕지만 엔진·부동소수점까지 포함한 기기 간 동일 결과를 보장하지 않는다.

R-merge 생성 위치는 소모한 두 중심의 평균, 초기 속도는 두 객체 속도의 평균으로 제안한다. wall clamp와 중첩 해소는 물리 엔진의 별도 검증 과제다. merge 처리 후 R-end를 평가한다. 기존 최고 단계 객체가 공간을 차지하므로 끝없는 성장 보상 대신 공간 관리 압력이 남는다.

첫 가치 행동은 사용자가 직접 떨어뜨린 물체가 첫 합체를 일으키는 순간이다. 이 사건은 재미를 느꼈다는 증거가 아니다. 다시 하기의 이유는 이전 실패에서 배운 배치를 시험하는 것, 다음 날 방문의 이유는 아직 검증하지 않은 개인 기록 도전 가설이다.

## 사업 가설

자체 비공개 테스트 경로부터 확인한다. 특정 게임 포털의 현재 약관·수익배분은 조사하지 않았고 입점을 확정하지 않는다. 광고 없음으로 핵심 반복 플레이를 관찰한 뒤 유통 후보 하나의 공식 조건을 조사한다. 예측 매출이나 리텐션 기준을 제시하지 않는다.
