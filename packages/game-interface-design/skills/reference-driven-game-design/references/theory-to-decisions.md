# Five reading lenses → design work

This is an original working checklist inspired by the sources below, not a reproduction or full summary of the books. Public excerpts/author articles/publisher descriptions were used. Do not claim access to entire books, proprietary text or numbered lenses. Check current accessibility before calling a source freshly verified.

## Learning and mastery — Raph Koster

Source: A Theory of Fun for Game Design, public excerpt: https://www.theoryoffun.com/excerpt.shtml
Ask what the novice notices, what relationships repeated play reveals and how an expert chooses differently. Produce two play situations and a counterexample where choices collapse. Treat learning as one lens, not the sole cause of enjoyment.

## Control and sensation — Steve Swink

Source: author's article, Game Feel: The Secret Ingredient (2007): https://www.gamedeveloper.com/design/game-feel-the-secret-ingredient
Use input, response, context, polish, metaphor and rules to connect action with perceivable consequences. Produce a feedback matrix and a small playable comparison plan. Feel belongs in early experiments, not only end-stage decoration. Do not infer latency or pleasure from a static screenshot.

## Multiple design perspectives — Jesse Schell

Source: official book page: https://schellgames.com/art-of-game-design
Examine the most relevant experience, choice, challenge, risk, economy and audience questions. Produce a bounded critique with changes and preserved decisions. These are our review prompts, not verbatim book lenses or claimed lens numbers.

## Sustainable play — Nicholas Lovell

Source: publisher's book overview, The Pyramid of Game Design: https://www.routledge.com/The-Pyramid-of-Game-Design-Designing-Producing-and-Launching-Service-Games/Lovell/p/book/9781138298897
Use momentary play, reasons to return and optional deeper engagement as separate planning questions. Produce a compact business hypothesis and an exclusion list. This application is a design proposal, not the publisher's promised commercial outcome. Do not impose a live-service economy on every tiny game.

## Implementation boundaries — Robert Nystrom

Source: Game Programming Patterns, author repository: https://github.com/munificent/game-programming-patterns/blob/master/book/game-loop.markdown
Keep game time, input and machine/render speed conceptually distinct. Produce responsibilities, event/state contracts and a test plan, not an obligatory pattern collection. Fixed-step simulation does not by itself prove cross-platform determinism.
