# Bounded work and resumption

Maintain one small Reference Log checkpoint after each meaningful stage:
`stage | decisions and source IDs | artifacts/revisions | checks actually run | open issues | next action`.
Record decision summaries, not private reasoning. Evidence claims always point to observable artifacts.

## User-facing decision summaries

At each meaningful checkpoint, show the user the important new or changed decisions in their language,
not only a link to a hidden log. Before dependent edits, explain the selected rule, level progression,
layout or visual direction; after verification, show what evidence confirmed or changed it. Usually
1–3 decisions suffice; omit trivial unchanged details. Explanation is not a permission handoff unless
an explicit review-wait or material unresolved decision requires it.

Use `Decision → Evidence → Application → Trade-off → Validation`:

- **Decision:** what was chosen and which rule/level/screen/component it affects.
- **Evidence:** inspected source title, section and URL/capture locator; the specific observed principle
  or behavior supporting the choice. An ID alone or a bibliography dump is not an explanation.
- **Application:** how the reference fits this player's task and what was adapted rather than copied.
- **Trade-off:** the relevant alternative not chosen and why, when an actual alternative exists; do not
  manufacture comparison work. Name costs, constraints and what is preserved.
- **Validation:** fact/user decision/proposal/assumption/unknown, executed check or next experiment,
  and the observation that would cause revision. A cited design principle does not verify chosen numbers.

Provide concise rationale summaries, not private chain-of-thought or a transcript of internal deliberation.
Distinguish what the source says from the agent's design inference and from observed playtest results.
If no source was inspected, say so and label the choice provisional; never invent a URL, quote, session,
approval or evidence strength. A valid user constraint can be the basis without an external citation.
Reuse the Reference Log's decision rows; code-only work may use the existing blueprint instead. Final
delivery repeats the decisive choices with readable source links and remaining evidence gaps.

Read the main skill and only current-stage references. At handoff/resumption verify changed inputs, prior decisions and stale dependent artifacts. Do not rerun settled interviews or reload all material as ritual.

A single owner integrates rule, UX and visual decisions. Available subagents may research a named source class or review an identified artifact. Give bounded input, required evidence, output structure and completion condition. Disclose unavailable tools; do not impersonate uncalled agents.

Prefer 1–3 representative screens and three high-impact corrections. Two to four real critique cycles are guidance, not mandatory score inflation. If the same structural issue persists twice, revisit its cause instead of adding decoration.

Default to independent safe work when one branch is blocked. No permission/license exceptions inferred from "quickly" or silence. Explicit approval-wait stops dependent writes, not read-only preparation.

This checkpoint protocol and any JSON validator are not a runtime hook. They cannot physically prevent agent calls or guarantee instruction adherence. Separate structural checks, observable execution and human acceptance.
