# World, HUD, controls and effects

Separate gameplay world, decision information, controls/menu and feedback. Assign each visible item a player question or perceivable consequence. Decorative prominence must not defeat collision readability or the next action.

If direction is open compare two substantive directions on one representative play state with the same content, viewport and score. Document silhouette, material metaphor, camera, depth, lighting, type character, semantic color and production cost. Color-swapped duplicates are not strategic alternatives. Reuse locked art direction; do not make every minor edit an exploration.

World: explain camera projection, play plane, visible vs judged geometry, occlusion and scale cues. Three-dimensional rendering is not a requirement for depth-axis gameplay. Effects may exaggerate feel without altering collisions, but distinguish the two.

HUD: prioritize only relevant score/progression, upcoming choices, danger and pause. No SaaS-dashboard habit of large stat cards, badges and menus obscuring the field. Menu layout and gameplay readability are separate tests.

Tokens: define only pilot-used primitive → semantic → component roles; e.g. decision warning vs destructive menu error can share a current value but remain different meanings. Include legible states, non-color cues, focus, motion and audio controls. Do not confuse assumed pixel values with measured source values.

Component contracts: purpose, slots, variants, pressed/disabled/focus state, responsive behavior, input capture, motion and source ownership. Use real licensed/importable assets in Figma mode through its source gate. Planning may name an unmet asset requirement, never call it produced.

Asset brief: locator/author, rights status, intended use, source vs modified copy, model/texture/animation/audio format needs, camera/lighting requirements, estimated budget and fallback. No fabricated downloads, copied character IP or hidden commercial restrictions. Concept stills are clearly labeled and do not replace production geometry or editable HUD.

Review at actual phone reading size, short/tall viewport and low-effect mode. Reduced effects preserve information and judged timing. Inspect effect bursts and floating scores for occlusion of the next placement/tap; do not assume static balance survives active play.
