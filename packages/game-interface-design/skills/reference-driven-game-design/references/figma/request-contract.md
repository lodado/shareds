# Figma request contract for games

## 1. Scope

Use the [game request](../game-request.md) as authority. Figma is opt-in. Inventory target, work area, source/brand authority, nodes, permissions and expected screens/states/viewports.

## 2. Decisions

Confirmed user decisions outrank proposals; approved brand outranks imported style; verified internal assets outrank external composition suggestions. Ask only about unresolved material conflicts. No purchase, source-library mutation, public sharing or destructive change from ordinary design permission. Research can continue independently.

## 3. Five planes

Strategy (experience/player need) → Scope (rules and included features) → Structure (journey and states) → Skeleton (field/HUD/control layout) → Surface (appearance). Diagnose upstream causes before polishing. A late rule change invalidates only dependent flow/screens; mark them stale and reverify.

Existing approval is reused. Showing a wireframe is not acceptance. Explicit review-wait stops target writes, including import probes. Record self-review separately from real user acceptance.
