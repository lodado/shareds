# Edit contract — 보존·번역·재해석을 구분한다

이 계약은 새 도구나 런타임 차단 장치가 아니라 편집 전후에 확인할 실행 규칙이다.
이미 주어진 지시에서 값을 추출한다. 사용자에게 같은 설문을 반복하지 않는다.
컴포넌트 연결 성공은 원본 디자인 충실도나 제품 완성도의 증거가 아니다.

## 1. 이번 변경의 모드와 범위

| 모드     | 허용되는 기본 변경                            | 기본적으로 보존할 것                                 |
| -------- | --------------------------------------------- | ---------------------------------------------------- |
| ASSEMBLE | 기존 섹션 이동·순서·상위 프레임 구성          | 섹션 내부 문구·스타일·이미지·컴포넌트 출처·내부 크기 |
| LOCALIZE | 번역·필요한 폰트 대체·줄바꿈·콘텐츠 높이 조정 | 원본 구성·타이포 위계·색·컨트롤 형태                 |
| FIDELITY | 지정 원본 재현, 명시된 콘텐츠/브랜드 치환     | 원본 레이아웃·크기·행간·여백·색·장식·인터랙션 모델   |
| RESKIN   | 명시적으로 승인된 시각 속성 변경              | 승인되지 않은 구조·내용·동작                         |
| REDESIGN | 명시적으로 승인된 구성/경험 재설계            | 범위 밖 섹션과 잠긴 제품·브랜드 계약                 |

새 화면에는 승인된 생성 범위를 REDESIGN으로 기록할 수 있다. 모드는 작업 종류이며 권한을 새로 부여하지 않는다.
혼합 작업은 섹션별 모드를 기록한다. ASSEMBLE 중 문구 수정이 필요하면 그 부분의 LOCALIZE/다른 변경 근거를
먼저 분리한다. 통합 요청 자체는 그 근거가 아니다. `ㄱㄱ`는 직전 합의 범위의 실행 승인이다.

편집 전 다음 짧은 표를 [request contract](request-contract.md)의 `source_authority.locked_constraints`와
`scope`에 연결한다. 새 요청 스키마 필드는 필요하지 않으며, 표는 decision/reference log에 둔다.

| 대상 file/page/node | 모드     | 기준 원본/버전         | preserve         | allowed changes  | 금지/미해결      |
| ------------------- | -------- | ---------------------- | ---------------- | ---------------- | ---------------- |
| 실제 읽은 Hero ID   | ASSEMBLE | 실제 기준 ID/관측 시점 | 내부 디자인 전체 | 상위 프레임 이동 | 이미지 제거 금지 |

현재 화면의 관측 사실, 사용자 결정, 에이전트 제안을 구분한다. 이전 시안이나 진행 승인을 자동으로 사용자
최종 채택으로 기록하지 않는다. 사용자가 반려하면 해당 변경을 보류하고 이전 기준과 새 지시를 대조한다.
“푸터가 아니라 전체”라는 정정은 검토 범위를 전체로 바꾸는 것이며 즉시 전체 재생성하는 허가는 아니다.

## 2. 원본과 브랜드의 우선순위

소스마다 역할을 기록한다: **재현 대상**, **구조 참고**, **시각 시스템**.
FIDELITY의 재현 대상은 색·타이포·여백도 기준이다. 구조 참고용 레퍼런스에 적용하는
“외부 색·폰트를 복사하지 않는다”를 이유로 재현 대상을 내부 기본값으로 덮지 않는다.
RESKIN에서는 승인된 시각 시스템으로 번역하되 원본의 정보 위계·비율을 잃지 않는다.
“템플릿은 출발점”이라는 규칙도 명시된 원본 보존을 무효화하지 않는다.
잠긴 브랜드와 사용자 지정 원본이 충돌하고 우선순위가 불명확하면 해당 선택만 확인한다.
연결된 mainComponent를 유지했다는 이유로 override를 무제한 허용하지 않는다.

## 3. 쓰기와 전송 복구

- 수정 전 기존 기준을 보존하고 별도 Working/Experiment 위치를 기록한다. 범위 밖 노드에는 쓰지 않는다.
- 한 번의 도구 호출 성공만으로 반영됐다고 하지 않는다. 실제 속성·하위 노드를 **read-back**한 뒤 화면을 본다.
- nested instance의 크기·layout override가 거부되거나 무시되면 원본 variant/property의 지원 범위를 확인한다.
  이 제약은 detach·재그리기·원본 main 수정의 허가가 아니다. 필요한 대안은 출처·편집 범위 규칙으로 다시 판단한다.
- 복사 전 source와 target을 확인한다. `Pasting…`가 멈추거나 응답이 불명확하면 target의 실제 노드 생성부터 확인한다.
  미완료·완료를 구분하지 못하는 동안 다시 붙여넣지 않는다. 늦게 완료된 노드도 중복 검사에 포함한다.
- 안전한 새로고침/재접속 후 대상 노드·진행 상태를 다시 확인한다. 앞선 시도가 종료됐고 대상이 없다는
  근거가 있을 때만 한 번 재시도한다. 결과가 여전히 불명확하면 해당 전송을 HOLD로 두고 독립 작업만 진행한다.
- 성공은 새 노드 ID, 원본 component key/연결, 문구·크기·스타일을 확인한 뒤 기록한다.
  **전송 실패를 다른 템플릿 재제작으로 우회하지 않는다.** 복구와 디자인 변경은 별도 결정이다.

## 4. 한국어는 재스킨이 아니다

원본 크기·행간·자간·weight와 역할을 읽고 한국어 폰트를 매핑한다. 모든 제목을 하나의 작은 스타일로
평준화하지 않는다. variable font의 weight가 API에서 누락/mixed이면 실제 text style·가용 폰트 정보를
추가 확인한다. 이름에 Regular가 보인다는 이유만으로 본문 weight로 단정하지 않는다.
Pretendard/Noto 등 가용 가족과 weight를 확인하고, 정확한 대응이 없으면 대체값과 차이를 기록한다.
예: Semi Bold 600을 Medium 500으로 대체했다면 동일한 weight라고 보고하지 않는다.

- 메뉴/버튼: 번역 후 한 줄 여부·가용 폭·Hug/Fill·최소 터치 영역을 확인한다.
- 본문: 콘텐츠 폭과 자동 높이·행간·부모 확장을 확인한다. 글자 잘림을 폰트 축소로 덮지 않는다.
- 범위 스타일이 있는 제목/본문은 역할을 보존한다. 공유 스타일/변수를 재사용하고 대체 스타일도 공유한다.
- FIDELITY의 콘텐츠 치환으로 높이가 바뀌면 원본 높이와 달라진 이유를 기록한다. ASSEMBLE에는 적용하지 않는다.

## 5. 네 가지 독립 게이트

| 게이트        | 필요한 증거                                                                  |
| ------------- | ---------------------------------------------------------------------------- |
| Source gate   | 지정 source file/node/component key, 실제 적용 node, 재사용 단위와 연결 상태 |
| Fidelity gate | preserve/allowed changes와 실제 override 대조, 원본과 가독 크기 나란히 비교  |
| Content gate  | 실제 제품 기능·이미지·링크와 일치, 승인된 placeholder와 미연결 상태 표시     |
| Layout gate   | 한국어 줄바꿈·잘림·겹침, 합의된 화면 폭·상태·반응형 검토                     |

ASSEMBLE은 이동 전후 동일 조건의 섹션 렌더와 내부 속성을 비교한다. 픽셀/PNG 비교는 보조 증거이며
렌더러 차이를 곧 디자인 변경으로 단정하지 않는다. LOCALIZE/FIDELITY는 변경된 문구 때문에 전체 픽셀 일치를
강요하지 않고 잠긴 레이아웃·타이포·색·여백을 검증한다. 새로운 화면은 승인된 기준과 비교한다.
원본 연결만 통과하거나 축소된 긴 페이지 한 장만 본 상태를 네 게이트 통과라고 하지 않는다.
정적 문구 테스트/fixture 검사는 실행 품질의 증명이 아니며 실제 Figma 검토를 대체하지 않는다.

## 6. 전달과 버전

원본 / 이전 검토본 / 현재 개선본 / 반려 보관본 / 현재 전달 frame을 명확하게 구분하고 링크를 준다.
데스크톱 시안, 모바일, 프로토타입, 제품 연동은 각각 **검증 / 미검증 / 범위 밖**으로 보고한다.
공유 스타일 존재, 실제 컴포넌트 연결, 라이브러리 publish 여부도 구분한다. 로컬 파생을 공식 시스템으로 부르지 않는다.
범위 내 미해결은 INCOMPLETE이며, 범위 밖 미작업을 숨기거나 불필요하게 범위를 넓히지 않는다.
스킬 자체의 Self-review를 사용자 채택이나 독립 QA로 승격하지 않는다.
