# Review — Look 근거로 납품하고 실제 피드백을 반영한다

Look의 비교와 [experience-design.md](experience-design.md)의 해당 동작 기록을 그대로 연결한다. 별도 7축 점수표나 고정 10줄 rationale를 다시 채우지 않는다.
구성/조형·브랜드 표현의 핵심 실패는 `incomplete`, 미열람은 `unreviewed`다. 부분 개선이나 예산 소진은 납품 완료가 아니다.

## 납품 설명

확인한 화면을 먼저 보여주고 **선택 이유 / 검증 / 잔여 범위**를 짧게 설명한다. 기존 브리프·comparison 링크로 충분하다.
코드 결과는 `loop:`·검사 대상·결과, 디자인 결과는 실제 프레임/미리보기·확인 상태를 연결한다. 없는 metrics를 만들어 채우지 않는다.

- technical: pass / fail / unmeasured / N/A — 실제 검사와 범위.
- design-self-review: ready / incomplete / unreviewed — 핵심 작업·위계·구성·브랜드 표현과 필요한 상태/일반·축소 모션의 근거.
- user-acceptance: accepted / rejected / not-obtained — 실제 응답만 기록.

미확정 사실·자산·접근 불가 범위를 숨기지 않는다. 자기검토 ready로 실제 사용자 반려를 뒤집지 않는다.
후속 수정안은 새 응답 전까지 not-obtained이고 이전 반려 기록은 보존한다. 기존 로그가 있으면 실제 응답만 추가한다.

## 피드백의 영향 범위

- **기존 기준 위반:** 어긋난 구간과 영향을 받는 인접/동일 역할 요소를 수정·확인한다.
- **새 선호/요구:** 바뀌는 결정만 확인하고 관련 범위에 반영한다.
- **모호한 불만:** 결과를 바꿀 최소 질문 또는 대비되는 시각 대안으로 구체화한다.

한 영역의 불만을 전역 브랜드 변경으로 확대하지 않는다. 미세 보수는 Look 예산 안에서, 큰 경험 해석 실패는 영향받은 결정으로 돌아간다.
기존 동작 테스트를 바꾸면 원래 역할과 승인된 변경/대체 계약을 연결한다. 테스트 삭제로 경험 보존을 주장하지 않는다.

## 사용자 검증 — 수행했을 때만 근거다

5초 보기 후 목적·첫 행동·기억할 요소를 묻거나, 실제 과업을 주고 멈춤·왕복·완료 인지를 관측할 수 있다.
이는 제안이지 실행 결과가 아니다. 소수 의견을 일반적인 선호·사용성 보증으로 확대하지 않는다.
같은 브리프의 화면을 블라인드 pairwise로 보여주고 적합성·선호 이유를 기록한다. 모델 심판과 사람 판단을 분리한다.
전환·리텐션 검증이 범위라면 실제 성공 사건·분모·기간을 정하고 계측한 결과만 보고한다. 클릭률 하나를 task 완료율로 대신하지 않는다.
