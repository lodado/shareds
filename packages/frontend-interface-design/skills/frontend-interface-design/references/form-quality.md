# Form quality — 구성 통과가 조형 완성은 아니다

새 UI·재디자인의 대표 구간을 확장하기 전, 또는 시각 반려를 복구할 때 읽는다. 작은 수정은 영향받은
요소와 주변만 검토하고, 충실한 재현·잠긴 디자인에는 새 취향이나 후보 제작을 강제하지 않는다.
[craft.md](craft.md)의 수치·토큰 기본값은 출발점이지 미감의 합격증이 아니다.

## 1. 부품이 아니라 한 화면에서 비교한다

실제 콘텐츠를 넣은 대표 구간과 그 안의 버튼·카드·목록·태그를 같은 배율로 함께 본다. 기존
무드보드/대표 UI slice를 재사용하며 별도 컴포넌트 갤러리를 의무 산출물로 만들지 않는다.

| 관점           | 확인과 교정                                                                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 실루엣·곡률    | 큰 패널, 카드, 버튼, 태그의 외곽이 중요도를 구분하는가? 모든 요소를 capsule로 만들거나 동일 radius를 대입하지 않고 크기·역할·중첩 관계를 조율한다.          |
| 타이포그래피   | 실제 제목의 줄 길이·줄바꿈·행간·무게, 메타정보 대비, 제목과 본문 간격을 함께 본다. 큰 글자만으로 위계를 만들지 않는다. 한글은 typography-ko.md를 우선한다.  |
| 광학 정렬·비례 | 버튼 높이와 좌우 여백, 라벨과 아이콘의 크기·간격·시각적 중심, 카드 안팎 여백이 균형 잡혔는가? CSS 중앙 정렬 성공을 광학적 완성으로 취급하지 않는다.         |
| 색면·표면      | 채도·명도·면적이 주인공을 돕는가? 배경·테두리·그림자·glow가 같은 경계를 중복 강조하면 필요한 표현만 남긴다. 모든 보조 요소가 강조색을 경쟁하지 않게 한다.   |
| 밀도·리듬      | 콘텐츠 분량에 맞는 높이와 여백인가? 빈 공간을 배지·장식으로 메우지 않는다. 의도된 넓은 여백은 보존한다.                                                     |
| 표현의 일관성  | 서로 다른 출처의 UI가 같은 타입·아이콘·표면 언어를 공유하는가? 표현적인 장치의 주연과 조연을 정한다. 절제·단색·특정 radius 자체를 정답으로 강제하지 않는다. |

카드는 독립된 탐색/선택 단위나 묶음 경계가 필요할 때 사용한다. 제목과 설명만 있다는 이유로
박스를 추가하지 않는다. `패널 → 카드 → 내부 박스 → pill`은 각 경계의 의미를 확인하고 불필요한
층은 여백·정렬·구분선으로 대체한다. pill은 짧은 식별·필터·상태에 맞춘다. 관계를 설명하지 못하는
거대 기술 태그를 자동 장식으로 쓰지 않는다. 읽어야 하는 장문은 기울기·지속 부유보다 안정성을
우선한다. 의도적인 브랜드 콜라주는 허용하되 텍스트·조작 영역과 모바일 구성을 보호한다.

## 2. 레퍼런스를 완성도 비교 기준으로 쓴다

관측한 레퍼런스와 결과를 전체 축소·실제 읽기 크기·부분 확대로 비교한다. 색·radius가 아니라
`관측한 관계 → 우리 콘텐츠에 맞춘 선택 → 실제 렌더 차이`를 근거로 삼는다. 예: 주 이미지 비중,
제목의 줄 수와 여백, 버튼의 라벨/아이콘 비례, 보조 정보 대비, 상태 간 안정성.
관측하지 않은 원본·모션은 추측으로 채우지 않는다. 원본의 자산을 못 쓰면 적합한 새 구도를 고른다.
기존 comparison에 원본/승인 보드와 대응 렌더, 보존한 관계, 남은 차이와 판단을 연결한다.
같은 색·SVG 존재·radius 일치·테스트 성공은 시각적 채택 근거가 아니다.

새 방향이 미정이거나 큰 구도가 반려됐으면 [art-direction.md](art-direction.md)의 소수 후보를
실제 콘텐츠로 비교한다. 주인공·정보 관계·밀도 등이 다른 안이어야 하며 색/easing만 바꾼 안을
대안으로 세지 않는다. 방향 선택이 위임됐으면 근거와 함께 직접 선택한다. 이미 승인된 방향이나
작은 컴포넌트 결함은 불필요한 전면 재설계 없이 같은 방향 안에서 교정한다.

## 3. 확장·납품 전 판단

아래는 브리프와 실제 화면에 해당할 때 반려할 대조 예시이지 스타일 금지 목록이 아니다.

| 관찰된 차이                                                     | 판단·복구                                                                                 |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 주인공 입자 군집이 작은 도식/보조 장식으로 바뀜                 | SVG 완료가 아니라 시그니처 미달. 구현 수단을 바꾸거나 승인 범위에서 다른 구도를 비교한다. |
| 제목만 바꾸면 다른 제품에도 쓸 무관한 표지가 핵심 면적을 차지함 | 실제 커버·발췌·코드·본문 도식으로 구성하거나 자산 없이 성립하는 편집형 구도를 고른다.     |
| 항목 폭은 다르지만 내용·비율·읽기 순서와 무관함                 | CSS 가변 폭을 fluid의 증거로 삼지 말고 실제 긴 제목과 행의 채움을 비교한다.               |
| 국소 불만 뒤 모든 섹션에 같은 박스/glow를 추가함                | 원인과 영향 범위를 확인하고 해당 구간의 관계·밀도부터 교정한다.                           |
| 축소하면 초점이 사라지고 읽기 크기에서는 제목이 구도를 무너뜨림 | 장식 보정이 아니라 주인공 비중·타입·배치를 다시 선택한다.                                 |

“밋밋함/허공/fluid/우주/멋있는 움직임”은 원인 진단이 아니라 경험의 단서다. 효과로 즉시 번역하지
말고 초점·묶음/정렬·콘텐츠 비율·광원/암부/깊이·시간적 전개 중 유력한 원인을 고른다. 해당 구간의
작은 전후 비교로 확인한다. 의도가 충분하면 재질문하지 않는다. 박스·gradient·미니멀리즘은 어느
것도 정답이나 금지가 아니며, 콘텐츠·합의된 브랜드 표현에서의 역할로 판단한다.

큰 재디자인이나 반려 복구에는 구현 설명과 테스트 수를 제외한 비평 관점을 사용한다. 브리프·실제
콘텐츠·비교 이미지/시간 근거에서 가장 큰 약점, 승인 방향보다 약해진 점, 삭제/재구성 대상을 찾는다.
별도 비평자는 선택 사항이며 동일 모델의 검토나 검토자 수를 인간 수락·품질 보증으로 쓰지 않는다.

대표 구간을 데스크톱·모바일, 적용 테마와 주요 읽기/조작 상태에서 실제로 본다. 다음을 별도로
판정한다. 관측하지 못한 항목은 통과 대신 `unreviewed`로 남긴다.

- 구성: 대표 콘텐츠의 이유, 주인공, 요소 관계와 읽기 순서가 성립하는가?
- 조형: 같은 화면의 실루엣·타입·색면·정렬·밀도가 선택한 방향과 어울리는가?
- 동작: [experience-design.md](experience-design.md)의 인과관계·연속성·안정된 읽기 상태가 성립하는가?

핵심 구성이나 조형이 실패하면 전체 확장을 멈추고 해당 선택으로 돌아간다. 글자/아이콘 정렬처럼
국소 결함이면 국소 교정한다. 색·간격·easing 보정으로 거절된 큰 구도를 재납품하지 않는다.
기존 [look.md](look.md)의 비교·무퇴행·보정 예산을 공유하며 독립 무한 루프를 만들지 않는다.
예산 소진 시 남은 결함과 다음 복구 경로를 보고한다. 수정안의 상대적 개선은 납품 가능 판정과 다르다.

이 검토는 미감의 자동 보장이나 사용자 승인이 아니다. technical, design-self-review,
motion-review, user-acceptance를 분리하고, 디자인 자기검토에는 구성/조형의 구체적 근거를 붙인다.
