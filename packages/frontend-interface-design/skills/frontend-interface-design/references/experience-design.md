# Experience design — UI · UX · motion을 함께 완성

여러 화면·분기·복구·모션이 필요한 경우에 해당 절만 읽고 Compose와 Look에서 같은 기록을 이어 쓴다. 새 장문 문서 대신 기존 브리프·출처표·검토 기록에 아래 필드를 합친다. 정적 우선은 구현 순서이지 정적 결과로 종료하라는 뜻이 아니다. 모든 화면에 모션이나 전환 퍼널을 강제하지 않는다.

## 1. 핵심 여정과 퍼널별 목표

이미 확인한 목적·콘텐츠·제품 정책을 사용하고 결과를 바꾸는 미결정 사항만 질문한다. 사용자 목표와 사업 목표가 다르면 구분하고 우선순위를 확인한다. AI가 만든 가설을 사용자 조사 결과로 기록하지 않는다.

단순 단일 화면은 조작·보이는 결과로 충분하다. 여러 화면·분기·복구가 필요한 때만 기존 브리프에 아래 전이 행을 쓴다.

| 현재 상태   | 조작      | 보이는 결과/도착         | 뒤로·실패/복구       | 실제 관측                 |
| ----------- | --------- | ------------------------ | -------------------- | ------------------------- |
| 실제 시작점 | 핵심 입력 | 완료 신호 또는 다음 상태 | 지원되는 복귀/재시도 | 근거 링크 또는 unobserved |

사용자/유입 상황과 목표에 필요한 행만 고른다. 모든 상태 조합을 전수 작성하지 않는다. 조작·도착·복구를 실행한 행과 미확인 행을 구분한다.

여정 이름과 단계 표기는 `ux-taxonomy.md → Part 5 UX 플로우 패턴`의 Sequence 형식(`이메일 입력 → 확인 안내 → 링크 → 대시보드`)을
빌려 쓰고, 페이지 역할은 `Part 4 페이지 유형`의 이름으로 적는다(경로 · 읽는 법은 `dictionary-recipes.md` §0). 사전의
Sequence는 후보 순서이지 제품 정책이 아니다. 우리 계약에 없는 단계는 넣지 않는다.

- 유입 의도나 사용자 상태가 다르면 필요한 여정을 분리한다. 신규/재방문이라는 이유만으로 화면을 무조건 분리하지 않는다.
- 핵심 여정의 성공 조건을 먼저 적고 각 퍼널 단계가 그 목표에 기여하는지 본다. 단계별 전환을 위해 전체 작업을 방해하지 않는다.
- 탐색·검색·상세 사이의 왕복, 뒤로 가기와 이탈도 포함한다. 모든 서비스를 구매·가입의 선형 퍼널로 바꾸지 않는다.
- 각 대상 섹션은 여정 단계·사용자 질문·핵심 행동·필요한 피드백과 연결한다. 기능 추가나 제품 정책 변경을 디자인 재량으로 확정하지 않는다.
- 지표가 필요하면 성공 사건·대상/분모·관측 기간·가드레일을 제안으로 구분한다. 데이터가 없으면 전환 개선을 주장하지 않는다. 분석 SDK·추적·개인정보 수집은 별도 범위다.

### 리텐션과 문구

재방문 가치 → 돌아올 계기/시점 → 이전 맥락 복원 → 지원되는 수단 → 사용자 통제 순으로 정한다. 실제 검색·저장·구독 등 제공 기능에 맞춰 문구를 쓴다. 없는 저장 기능·미정 발행 주기를 약속하거나 죄책감·허위 긴급성으로 재방문을 유도하지 않는다. 알림/구독은 동의·해지·빈도 제어와 연결한다. 일회성 작업이면 리텐션은 이유와 함께 N/A로 두고 불필요한 CTA를 추가하지 않는다.

## 2. 구현 전 원본과 기존 경험 관측

실제 사이트를 참고하는 재디자인은 **시각 값 / 구성 / 시간적 경험**을 별개로 관측한다. 접근 가능한 원본의 첫 진입, 대기 후 상태, 주요 스크롤 구간, 대표 조작을 확인하기 전 제품 코드를 변경하지 않는다. 스크린샷·토큰 문서·브랜드 이름은 현재 라이브 경험 전체의 증거가 아니다. 모션의 미기재는 무모션 요구가 아니다.

문서와 라이브 사이트의 차이를 기록한다. 사용자 지정 원본을 라이브 사이트로 자동 교체하지 않으며 큰 방향이 갈리는 충돌만 질문한다. 접근 불가면 `unobserved` 범위와 보수적인 기존 경험 보존안 또는 필요한 자료를 밝힌다. 기억으로 동작을 만들고 관측했다고 하지 않는다.

기존 화면도 `요소 → 역할 → 유지/재해석/삭제 → 근거·대체 경험`으로 짧게 기록한다. 콘텐츠 교체 허용을 기능·상호작용·시간적 연출의 포괄 삭제 권한으로 확대하지 않는다. 사소한 hover마다 승인을 받지는 않지만 핵심 경험을 삭제하는 불명확한 결정은 확인한다. import가 사라졌다는 사실은 경험이 불필요하다는 근거가 아니다.

핵심 특징은 기본 3–5개 이내로 선정하되 작은 작업에 수량을 강제하지 않는다:

`관측 특징·출처 → 우리 콘텐츠/여정에서의 역할 → 유지/재해석/제외 → 구현 위치·자산 가능성 → 확인 방법`

색과 로고를 가려도 채택한 구조나 움직임을 설명할 수 있는지 자기비평한다. 원본과 목적이 다르면 그대로 복제하지 않는다. 관측은 자산 재사용 허가가 아니다. 원본 영상·마스코트를 사용할 수 없으면 역할을 살린 합법적 대안이나 자산 없이 성립하는 구성을 선택하고 이탈을 기록한다. 일반 fade-in이나 의미 없는 도형은 자동 대체재가 아니다.

## 3. 모션을 구성과 함께 설계

역할은 **조작 피드백 / 정보 설명 / 브랜드 표현 / 근거 없는 장식**으로 구분한다. 브랜드 표현도 정당한 역할이며 직접적인 클릭 수 감소로만 정당화하지 않는다. 마지막 범주는 삭제 후보지만 기존 모션 전체를 같은 이유로 제거하지 않는다.

| 요소·역할      | 패턴(사전)                       | 트리거              | 시작 → 종료 상태      | 시간/스크롤 범위   | 반복·중지·사용자 제어 | 모바일      | reduced-motion | 근거                     |
| -------------- | -------------------------------- | ------------------- | --------------------- | ------------------ | --------------------- | ----------- | -------------- | ------------------------ |
| 실제 관측 요소 | 이름 · 의존 라이브러리 또는 없음 | 진입/조작/가시성 등 | 콘텐츠·활성 상태 포함 | 관측값 또는 미관측 | 화면 밖 재생 중지 등  | 확인/미확인 | 정지·축소 대안 | 직접 관측/추정/제안·출처 |

`패턴` 열은 `design-taxonomy.md → Part 2 인터랙티브 패턴`의 이름과 의존 라이브러리(예: `PinnedContentSwap` ·
GSAP ScrollTrigger / IntersectionObserver)를 적는다(경로 · 읽는 법은 `dictionary-recipes.md` §0). 이름은 사전에서 오고
트리거 · 시간 · reduced-motion 대안은 직접 결정하며 두 출처를 섞지 않는다. 스크롤 · 스티키 패턴은 채택 전
`layout-taxonomy.md → 17–18`의 `Avoid For`(예: parallax는 대시보드 · 접근성 민감 화면)를 확인한다.

단일 이미지로 타이밍을 확정하지 않는다. 카드 이동과 미디어 재생 조건도 구분한다. 짧은 duration 기본값은 일반 조작 피드백용이다. 브랜드 연출·스크롤 내러티브·영상의 시간축까지 200ms로 제한하지 않는다. 관측값 또는 합의된 역할에 맞춰 선택하며 모든 요소에 같은 효과를 복제하지 않는다.

접근성·사용자 제어·읽기·성능을 함께 지킨다. 키보드에서 상태 피드백을 없애거나 필수 조작을 애니메이션 종료까지 막지 않는다. 원본이 reduced-motion에서도 자동 재생한다고 그 결함까지 복제하지 않는다. 축소 설정에서는 정보·탐색·조작을 보존하는 정지/직접 전환 대안을 제공한다.

실제 콘텐츠와 핵심 동작을 담은 대표 구간으로 해석을 먼저 시험한 뒤 전체에 확장한다. 기존 승인 안에서는 별도 승인 관문을 만들지 않는다. 정적인 정보 위계가 성립하는지와 핵심 동작이 성립하는지를 모두 본다. 모션을 위해 카드 높이·스크롤 길이를 부풀리지 않는다. 부분 적용은 토큰·모션·자산의 경계를 유지하고 다른 경로를 전역 무모션/테마 변경으로 훼손하지 않는다.

## 4. 정적·시간적·여정 검토와 납품

### 자연스러움 — easing보다 인과관계와 연속성

각 주요 동작에서 `무엇 때문에 → 어떤 대상이 → 무엇으로 바뀌고 → 어디서 안정되는가`를 설명한다.
같은 대상의 변화는 위치·형태·선택 표시 등 추적할 단서를 남긴다. 작은 조작에 과도한 이동을 붙이거나
모든 요소에 독립 부유 루프를 추가하지 않는다. 읽는 본문과 조작 타깃은 안정적으로 유지하고, 진입
효과 때문에 콘텐츠 접근을 기다리게 하지 않는다. 스크롤 연출은 중간 지점·역방향·빠른 통과에도
현재 상태와 읽기 순서가 이해되는지 확인한다. hover만을 유일한 정보·조작 경로로 삼지 않는다.
브랜드 모션은 정보 설명 외에도 분위기를 전달할 수 있다. 전달할 인상과 주인공과의 관계를 정하고
가독성·접근성을 보호한다. 모바일·축소 설정에서는 같은 안무보다 같은 정보와 작업 완료를 보존한다.
정지 장면만으로 일반 모션을 통과시키거나, 모션 구현 성공으로 조형 품질을 통과시키지 않는다.

### 검토 근거

같은 대표 시나리오로 원본과 결과를 비교하되 관측과 해석을 구분한다.

- 정적: 실제 콘텐츠, 위계·밀도·대비, 작은 화면, 키보드 접근, 누락·잘림을 확인한다.
- 시간적: 일반 모션 설정에서 진입·대기·주요 조작·스크롤 중간·종료 상태와 재생/중지를 확인한다. 짧은 녹화 또는 재현 가능한 브라우저 스크립트와 실행 관측 기록을 남긴다. 스크립트 작성만으로 실행 검증을 주장하지 않는다.
- 축소 모션: 별도로 같은 작업을 완료할 수 있는지 확인한다. reduced-motion 스크린샷은 일반 경험 검증의 대체물이 아니다.
- 여정: 핵심 작업 완료, 다음 행동과 종료, 빈 결과·실패·뒤로 가기·재방문 맥락을 실제 지원 범위에서 확인한다. 조작 수가 적다는 이유만으로 이해·복구를 희생하지 않는다.

기존 technical / design-self-review / user-acceptance 판정에 다음 근거를 연결한다:

| 검토 축               | 상태                                  | 근거                                 |
| --------------------- | ------------------------------------- | ------------------------------------ |
| journey-review        | pass / fail / unobserved / N/A        | 대표 여정·완료/복구 관측             |
| reference-translation | ready / incomplete / unobserved / N/A | 핵심 특징 대응·의도적 이탈           |
| motion-review         | pass / fail / unobserved / N/A        | 일반 설정·축소 설정 각각의 실행 증거 |

필요한 축이 fail/incomplete/unobserved면 해당 범위를 완료로 보고하지 않는다. N/A에는 정적 시안처럼 합의된 출력 범위에 따른 이유가 필요하다. 기술 통과가 누락된 핵심 특징을 보충하지 않으며 자기검토는 사용자 만족·전환·리텐션 개선의 증거가 아니다.

기존 동작 테스트를 삭제·완화할 때 원래 보장하던 역할과 승인된 요구 변경 또는 명시적인 대체 계약을 연결한다. 유지되는 역할에는 새 회귀 검사를 연결한다. 새 구현에 맞춰 테스트만 지우고 통과 수로 경험 보존을 주장하지 않는다.

계측 실패는 구현 결함 / 관측 누락 / 도구 집계 한계로 분류한다. 원자료·범위와 별도 판정을 남기며 점수를 맞추려고 토큰을 전역화하거나 무의미한 var() 참조를 늘리거나 임계값을 조용히 낮추지 않는다.

큰 경험 해석 오류는 미세 보정 예산으로 덮지 않는다. 실패한 시도와 영향을 받은 결정을 기록하고 해당 적용을 멈춘 뒤 원본 해석/브리프로 돌아간다. 새 결정이 필요한 부분만 확인하고 이미 위임된 범위의 수정은 진행한다. 무한 재시작하거나 예산 종료를 완료 근거로 쓰지 않는다.
