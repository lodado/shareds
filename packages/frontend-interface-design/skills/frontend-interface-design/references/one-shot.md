# One-shot — 요청 한 번에 끝낸다, 그리고 무엇이 이기는지 정한다

이 skill은 **사용자 요청 한 번**에 화면을 낸다. 중간에 묻지 않는다. 그러려면 두 가지가 미리
정해져 있어야 한다: **누가 이기는가**(우선순위)와 **묻지 않고 무엇을 정하는가**(선택자).

## 1. 우선순위 — 위가 아래를 이긴다

```
1. 안전 · 권한 · 법                 결제 · 삭제 · 권한 정책은 frontend-oracle-design 소관.
                                    없으면 NEEDS_DECISION. 무단 자산 · 코드 복제 금지.
2. 접근성 하한                       대비 4.5:1 / 3:1, 탭 타깃, focus-visible, 320px overflow 0.
                                    레퍼런스가 이걸 어기면 레퍼런스를 고친다(이탈로 기록).
3. 사용자 소유 소스 · 잠긴 DESIGN.md 사용자의 값이 언제나 팩과 계보를 이긴다.
4. Reference Pack의 observed 값      팩이 있고 관측 증거가 있으면 그 값이 계보의 기본값을 이긴다.
5. Reference Pack의 estimated 값      관측값에서 유도한 값. 계보와 충돌하면 팩이 이기되 근거를 적는다.
6. 계보(lineage)의 기본값            팩이 없거나 unverified면 여기가 시각 권위다.
7. craft 기본값 · 미적 선호          위 어느 것과도 충돌하지 않을 때만 적용되는 마감 기본값.
```

**5–7단은 법이 아니라 기본값이다.** `craft.md`의 12개 기본값과 상시 규칙의 미적 조항(중립 틴트 ·
accent 5% · 폰트 2개)은 **레퍼런스 증거가 없을 때의 기본값**이다. 관측된 팩이 다른 값을 말하면
팩이 이긴다. 예: Vercel 팩의 primary CTA는 무채색 반전이라 "accent는 유채색"이라는 기대와
어긋나지만, 관측이 이긴다. 어긋난 자리는 decision record에 한 줄로 적는다.

안전 · 권한(1단)이 아니면 **묻지 않는다.** 나머지는 가정으로 적고 진행한다.

사용자가 제공한 사용 권한이 있는 자산과 라이선스가 허용하는 오픈소스 코드는 재사용한다.
출처 · 고정 버전 · 라이선스 조건을 기록하고, 저작권 고지 등 요구사항을 보존한다.

## 2. 선택자 — 발화 하나에서 팩 · 페이지 · 기기를 정한다

```bash
node <skill>/scripts/pack.mjs --route "<사용자 발화>" --task <우리 task>
```

`mode` · `packId` · `evidenceStatus` · `taskMatch`가 나온다. 그다음은 표대로다.

| mode                            | 시각 권위 | 첫 문장에 반드시   | layout slots           |
| ------------------------------- | --------- | ------------------ | ---------------------- |
| `reference-informed-adaptation` | 팩        | 관측 날짜 · URL    | scope=full일 때만 사용 |
| `unverified-reference`          | 계보      | "브랜드 재현 아님" | 참고만, 계보 우선      |
| `lineage`                       | 계보      | 레퍼런스 없음      | 계보의 매크로구조      |

**task가 다르면 layout을 버린다.** 마케팅 랜딩 팩으로 대시보드를 만들 때 hero와 display 64px을
가져오면 그건 팩을 잘못된 task에 적용한 것이다. 팩의 `taskTransfer`가 무엇을 옮기고 무엇을
버리는지 말한다 — 보통 토큰 · radius · 간격 리듬 · ui/caption 타입 역할은 옮기고, display 스케일과
섹션 순서는 버린다.

**페이지 · 기기**는 발화에서 읽고, 없으면 아래 기본값을 가정으로 적는다.

| 신호                                      | 기기 기본값       | 페이지 기본값   |
| ----------------------------------------- | ----------------- | --------------- |
| "앱" · "모바일" · 한국어 커머스 · 금융    | mobile 390        | home / feed     |
| "대시보드" · "관리자" · "콘솔" · "테이블" | desktop 1440      | product surface |
| "랜딩" · "소개" · "가격"                  | 둘 다(375 · 1280) | landing         |
| 신호 없음                                 | 둘 다(375 · 1280) | 팩의 `pages[0]` |

## 3. 묻지 않는다 — 대신 가정을 적는다

Rationale에 `가정:` 줄로 남긴다. 예: `가정: 기기=mobile 390(발화의 "앱"), 페이지=home,
데이터=placeholder, 다크 테마 미요구`. 사용자가 다르다고 하면 그때 고친다. 되묻는 것보다 싸다.

예외는 1단뿐이다: 결제 · 삭제 · 권한 · 개인정보처럼 **정책이 필요한 동작**, 또는 사용자 소유
`DESIGN.md`를 덮어써야 하는 상황. 그때만 `NEEDS_DECISION`으로 멈춘다.

## 4. 잠금과 다양성의 관계 — 충돌 아님

- **잠긴 DESIGN.md · 채택된 팩이 있으면 매크로구조를 반복해도 된다.** 일관성이 목적이고,
  같은 시스템의 두 화면이 닮는 것은 결함이 아니다.
- **다양성 규칙은 잠금이 없을 때만 적용된다.** 같은 프로젝트에서 소스도 팩도 없이 계보만으로
  만드는 화면이 연달아 나올 때, 마지막 화면과 매크로구조가 같으면 그것은 템플릿 반사다 —
  다른 매크로구조를 고른다(`adaptation.md` § 6).
- 판정: `.design/log.json`의 마지막 항목에 `locked: true`(팩 또는 DESIGN.md)면 다양성 규칙을
  건너뛴다. `locked: false`면 적용한다.

## 5. 상태(state)는 컴포넌트마다 다르다

상시 규칙 7의 8종은 **인터랙티브 컴포넌트의 최대 집합**이지 모든 요소의 의무가 아니다.

| 컴포넌트                    | 필수 상태                                                              |
| --------------------------- | ---------------------------------------------------------------------- |
| 제출 · 액션 버튼            | default · hover · focus-visible · active · disabled · loading          |
| 링크 · 탭 · 토글            | default · hover · focus-visible · active · current(선택)               |
| 입력 · 선택                 | default · hover · focus-visible · disabled · error · (해당 시 success) |
| 목록 · 표 · 피드            | default · loading · empty · error (행 hover는 선택)                    |
| 정적 텍스트 · 이미지 · 배지 | 없음                                                                   |

"버튼에 success 상태가 없다"는 결함이 아니다. "폼 제출 버튼에 loading이 없다"는 결함이다.

## 6. 색 · 폰트 수 — 개수가 아니라 가족과 역할

- 색: **중립 계열 1개 + 액션 accent 1개 + 상태색(성공 · 경고 · 위험)**이 기본이다. 중립 계열이
  6단계여도 한 가족이면 하나로 센다. 세는 것은 hue 가족이지 토큰 개수가 아니다.
  팩이 추가 hue를 관측했다면(예: 가격용 경고 hue) 그것은 역할이 있는 색이므로 허용된다.
- 폰트: **가족 ≤2**는 본문 · display 가족을 뜻한다. 같은 가족의 굵기 · 폭 변형은 하나로 센다.
  모노스페이스는 코드 · 숫자 역할이면 세 번째로 허용한다(팩이 관측했다면 근거가 있는 것이다).
- `gates.json`의 `fontFamilyCount`는 렌더된 **가족 이름의 개수**를 세므로, 모노를 쓰는 브리프는
  브리프의 `gates`에서 3으로 올린다. 게이트를 임의로 완화하는 것이 아니라 브리프에 선언한다.

## 7. 한 번의 요청 안에서 도는 루프

Build 뒤 [`look.md`](look.md)를 **1회 렌더 + 최대 2회 보수**로 돈다. 사용자에게 돌아가기 전에
끝난다. 게이트 통과가 목표고, 통과하지 못한 항목은 Rationale의 "남은 결함"에 적는다.
