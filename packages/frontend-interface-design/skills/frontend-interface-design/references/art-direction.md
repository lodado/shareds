# Art direction — 주인공을 정하고 말 대신 만든다

새 방향이 필요한 구간에서만 사용한다. 이미 승인된 방향·Fidelity는 그대로 잇고 중복 무드보드나 승인을 만들지 않는다.
사실·필수 콘텐츠·자산 처리의 빈칸은 [discovery.md](discovery.md)와 [brand-intake.md](brand-intake.md)로 확인한다.

## 1. 시그니처를 만드는 네 동작

1. **주인공을 정한다.** 실제 제목·숫자·이미지·선택 결과 중 화면에서 기억해야 할 것을 고른다. 언제나 CTA나 hero일 필요는 없다.
2. **표현의 중심을 고른다.** 새 방향이면 서체·구도·색 중 하나를 과감하게 쓴다. 나머지는 주인공을 받친다. 고밀도 도구는 정렬·정보 구조 자체가 시그니처일 수 있다.
3. **말 대신 만든다.** 실제 길이 콘텐츠로 대표 구간을 제작하고 desktop/mobile에서 연다. 방향 해석이 갈릴 때만 구조가 다른 작은 후보 둘을 비교해 하나를 추천한다. 색만 다른 스킨은 대안이 아니다.
4. **같은 언어로 확장한다.** 타입 대비·정렬·색 역할을 다음 섹션과 주요 상태에 잇는다. 하나의 특징을 일관되게 쓰되 모든 섹션을 같은 큰 글씨·카드·모션으로 복제하지 않는다.

| 입력                         | 제작 조작                                                              | 실제 결과에서 볼 것                                         |
| ---------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| 이미지 없는 서점·출판 콘텐츠 | 긴 제목을 주인공으로, 짧은 메타정보와 비대칭 정렬로 편집 리듬을 만든다 | 모바일 읽기 순서, 긴 한글 제목, 빈 이미지 패널 없이 글 발견 |
| 이미지가 있는 제품 상세      | 이미지 점유·크롭·옵션 영역의 관계를 잡고 선택 결과를 인접시킨다        | 다른 제품·긴 옵션명에서도 구도와 선택 피드백 유지           |
| 따뜻한 소비자 서비스         | 넓은 브랜드 색면과 타입 위계를 쓰고 행동·상태색의 의미를 분리한다      | 면적 비율이 아니라 가독성·행동 구분·기억할 요소             |

[기본 예시](../exemplars/README.md)에서 콘텐츠가 맞는 하나만 선택한다. 예시의 장식을 베끼는 대신 입력→조작→결과를 가져온다.
이미지가 없으면 제목·본문·정렬로 구성한다. 필요한 실제 자산을 임의 도식·후기·수치로 대체하지 않는다.

## 2. 대표 구간과 실제 열람

대표 구간은 실제 카피·데이터 길이·보유 자산이 들어간 HTML/design frame/image 등 열 수 있는 artifact다.
글 발견이면 대표 글과 목록, 제품 선택이면 제품과 옵션을 함께 보여준다. 별도 보드가 필요 없으면 이 구간이 방향 근거다.
코드는 프로젝트 브라우저 또는 `scripts/render.mjs --in <slice.html> --out <render-dir>`로 렌더한다.
큰 화면/작은 화면을 **직접 열어 본 뒤에만** `board-viewed: yes` 또는 `visual-reviewed: yes`로 기록한다.
생성·캡처 성공과 실제 열람은 다르다. 미열람은 `unreviewed` / `visual-reviewed: no (code-only)`이며 적용 완료가 아니다.

기존 브리프 또는 `DESIGN.md`에 선택 이유와 artifact·실제 열람 범위를 한 번 연결한다. 별도 고정 길이 기록은 필요 없다.
사용자 선택/명시적 위임으로 방향을 정하고 이후 세부 선택은 직접 끝낸다. 데모 콘텐츠 동의는 방향 승인으로 확대하지 않는다.
잠긴 디자인·소유 소스·기존 필수 승인 범위가 우선이며 명시적 재디자인도 허용 범위만 바꾼다.

## 3. 레퍼런스는 관계를 관측한다

정확한 URL·프레임·관측일/버전과 **본 범위**를 적고, 가져올 정보 관계와 제외할 장식·자산을 구분한다.
실제 사이트면 [clone-study.md](clone-study.md)의 대표 구간 관측→재현→다른 콘텐츠 치환을 필요한 경우에만 쓴다.
문서·정지 이미지로 모션을 관측했다고 하지 않는다. 동작은 전후/시간축 근거를 별도로 남긴다.
상충하는 방향을 평균 내어 섞지 않는다. 선택한 한 시스템 안에서 섹션별 출처와 구성을 조정한다.
사조가 도움이 될 때만 `design-movement-converted.md`의 Visual Cues·Cost를 구체적인 선택으로 옮긴다(`dictionary-recipes.md` §0).

## 4. 이미지 제작 브리프 — 자산이 없고 제작이 승인된 경우에만

제공된 자산으로 성립하는 화면에는 쓰지 않는다. 제작 승인 후 `visual-asset-taxonomy.md`의 기법·구조·표면으로 브리프를 쓰고 수단(SVG / Image / Hybrid)을 고른다.
사진풍이면 `generative-image-taxonomy.md`, 상업 사진이면 `commercial-photographic-taxonomy.md`의 해당 장르만 참고한다(`dictionary-recipes.md` §0).
로컬 사전이 없으면 패키지 요약을 쓰고 그 한계를 밝힌다. 새 의존성이나 이미지 생성을 자동 요구하지 않는다.
제작 결과도 직접 열어 확인하고 사용자 승인 전까지 "확인 필요"다. 로고·실제 인물·제3자 제품을 지어내지 않는다.

## 근거의 범위

- [Lucero, 2012](https://doi.org/10.1145/2317956.2318021): 무드보드의 framing·aligning·directing 관찰; 매 작업에 보드를 강제하는 근거는 아니다.
- [Dow et al., 2010](https://doi.org/10.1145/1879831.1879836): 웹 광고 병렬 대안 실험. 작은 후보 둘은 이번 작업 예산이지 품질 보장 수치가 아니다.
