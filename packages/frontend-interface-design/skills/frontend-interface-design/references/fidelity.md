# Fidelity — 소스를 값 단위로 옮긴다

사용자가 소유한 디자인 소스(Figma · 스크린샷 · design.md · 토큰 파일 · 기존 화면 · 자기
사이트 URL)가 있을 때의 절차다. 목표는 해석이 아니라 재현이다. Agent의 취향은 들어가지 않는다.

## 원칙

1. **추정하지 않는다.** "16px쯤"은 값이 아니다. 소스에서 읽을 수 있으면 읽고, 못 읽으면 묻는다.
2. **소스에 없는 것을 더하지 않는다.** gradient · shadow · motion · 아이콘 · 카피 · 섹션 어느 것도.
   소스가 밋밋하면 밋밋하게 만든다.
3. **소스에 있는 것을 빼지 않는다.** 아래 "허용된 이탈"만 예외이며 전부 기록한다.
4. **모든 state를 옮긴다.** 소스에 없는 state는 "소스에 없음"으로 기록하고 ui-checklist 기본값으로 채운다.
5. **조작 모델을 먼저 판별한다.** 클릭 전에 스크롤. 틀리면 CSS 수정이 아니라 재작성이다.

## 허용된 이탈 — 이것만, 그리고 기록

| 이탈            | 조건                                       | 기록 형식                               |
| --------------- | ------------------------------------------ | --------------------------------------- |
| 대비 보정       | 텍스트 4.5:1 · UI 3:1 미달                 | `deviation: contrast <요소> <전→후>`    |
| 터치 타깃 확장  | 44px 미만. 시각 크기 유지, hit area만 확장 | `deviation: hit-area <요소>`            |
| focus-visible   | 소스에 focus 상태 없음                     | `deviation: focus <요소>`               |
| 반응형 보완     | 소스가 한 뷰포트만 제공                    | `deviation: responsive <뷰포트> <처리>` |
| 빠진 state 보완 | loading · empty · error · partial 없음     | `deviation: state <state> <처리>`       |
| reduced-motion  | reduce 환경에서 소스 motion 제거           | `deviation: motion-reduce <요소>`       |
| 시맨틱 교정     | div 버튼 → button, 헤딩 순서               | `deviation: semantics <요소>`           |

이 표에 없는 이탈은 사용자에게 묻는다. "더 낫다고 생각해서"는 이탈 사유가 아니다.

## 추출 — 소스 종류별 위임

| 소스             | 위임                                                                  | 위임 대상이 없으면                                 |
| ---------------- | --------------------------------------------------------------------- | -------------------------------------------------- |
| Figma            | `figma:figma-design-to-code`                                          | 스크린샷으로 격하, 아래 스냅 규칙, 사용자에게 알림 |
| 자기 사이트 URL  | 레포의 `clone-website` Phase 1(스크린샷 · 토큰 · 조작 sweep · 반응형) | 아래 최소 추출                                     |
| 기존 화면(코드)  | 없음 — 기존 컴포넌트와 토큰을 그대로 재사용                           | —                                                  |
| design.md · 토큰 | 없음 — 파일이 곧 표                                                   | —                                                  |
| 스크린샷         | 없음 — 아래 스냅 규칙                                                 | —                                                  |

**스냅 규칙.** 스크린샷만 있으면 값은 프로젝트 토큰 스케일의 가장 가까운 단계(spacing ·
type · radius)에 스냅한다. 스냅한 값마다 `snapped: <요소> <추정→토큰>`으로 기록한다.

**최소 추출**(위임 대상 없을 때). 컴포넌트마다 아래 8줄. 빈 줄을 두고 build로 넘어가지 않는다.

```md
### <컴포넌트> — 소스: <위치>

- 조작 모델 / 레이아웃(방향 · gap · padding) / 타입(역할별 토큰) / 색(역할별 토큰)
- radius · shadow · border / motion(속성 · duration · easing 또는 없음)
- state: default · hover · focus · active · disabled · loading · error · empty (없는 건 "소스에 없음")
- 반응형: 320 · 768 · 1280 (소스 제공 뷰포트 표시) / 카피: 원문 / 이탈: 기록 형식 또는 없음
```

## Self-review — 소스와 나란히

320 · 1280에서 섹션별 비교. 차이마다 한 줄로 분류한다.

| 차이                    | 분류        | 처리                     |
| ----------------------- | ----------- | ------------------------ |
| 추출 표와 다름          | 구현 오류   | 표대로 고친다            |
| 표는 맞는데 소스와 다름 | 추출 오류   | 재추출 후 표와 구현 수정 |
| 허용된 이탈 표에 있음   | 의도한 이탈 | 기록 확인                |
| 그 외                   | 무단 창작   | 제거                     |

픽셀 diff는 `frontend-visual-qa`가 명시 요청될 때 그쪽 몫이다.

## Rationale — Fidelity 형식

```md
## Rationale — <화면>

mode: fidelity source: <종류 · 위치> extracted-by: <위임 스킬 또는 최소 추출>
review: T4 H5 S4 E5 R5 X5

1. 이탈: <목록> — 각각 이유 한 줄.
2. 소스에 없어 기본 규칙으로 채운 state: <목록>.
3. 스냅 · 추정한 값: <목록 또는 없음>.
4. 검증 필요 가정: <소스 해석이 갈렸던 지점 하나>.
```
