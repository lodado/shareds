# State ownership and type contract selection

At an exposed type/state boundary use the existing owner first: query/router/form/server state, then
derived values, local independent state and only necessary explicit discriminated state. Never create
a status union just because a card describes state, one member per screen, duplicated neighbor flags
or unapproved product states. Async/order/retry/duplicate-submit transitions map to approved invariants.
Use actual installed pinned type-fest utility in the real consumer relation, positive/negative TypeScript
witnesses and meaningful positive-count property sampling of approved contract relations. Enumeration
or passing tsc alone does not replace required property evidence. Read [type environment](../type-environment.md)
when compiler/config/witness inclusion/checker changes. No unrelated dependency/compiler changes.

# Compiler-witness-gated advanced contracts

Adopt an advanced type only with a useful source-backed boundary relation, real type-fest consumer
and positive/negative witnesses under pinned effective compiler/config. Prefer installed built-ins and
the simplest useful public seam. The actual checker must prove the claimed relation, not an unrelated
fixture. Record utility/version, witness location, expected diagnostics and actual reported results.
Pair applicable async/order relations with approved-invariant property sampling, seeds/count/limits and
case evidence. No unrelated compiler/dependency changes, dummy aliases or widened contracts for GREEN.
