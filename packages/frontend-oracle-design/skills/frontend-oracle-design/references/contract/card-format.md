# Contract card and realization plan

The existing `oracle.md` card format remains the source, with Verification Profile, outcome/non-goals,
source identities, approved rows/scenarios, full-product dimensions/constraints/dispositions, questions,
realization plan and actual User Confirmation. Follow [authoring](authoring.md) and [Space](space.md).
No second schema. For each core mechanism name real target, controlled boundary, completion barrier,
observable assertions and applicable method. Include inherited × new × runtime interactions and
async/order paths, not merely unit/integration/e2e labels. Generic given records preserve falsy values.
Record approved visual Design Change Confirmation and outcome-changing architecture/backend decisions
before final lock. Missing approved dependencies name package/version/owning manifest, no silent install.
New Draft is shown in full, existing revision as semantic delta with all open questions/review inputs.
Plans are not evidence. Only actual approval permits subsequent CHECKED whole-card hashing.
