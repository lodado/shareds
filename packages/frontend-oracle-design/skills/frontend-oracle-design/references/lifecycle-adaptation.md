# Lifecycle adaptation: conditional investigation and work units

Read only for unclear existing-system ownership, cross-boundary impact or single-card milestone grouping.
Known owners and sufficient approved sources for a small change do not need this node. Risk in common
sets minimum evidence independently of task size. No new score, state, approval gate or planning artifact.

Trace the affected journey, state/API/side-effect owners, shared types and real verification locations.
Distinguish observed as-is, approved to-be and unknown in the existing journal, never infer policy from
code/tests/browser behavior. Reuse approved documents, do not reverse-engineer the whole repo. Source
conflicts use common feedback and controller questions. Conditional problem-definition review follows
selected-profile policy sources, including important dismissals/escapes.

Keep outcomes sharing policy/state/effects/files in one card. Non-overlapping test-owned rows may use
existing milestones without new states or budget resets. Name integration ownership and real target in
current-profile realization plans. Independent GREENs do not establish combined-journey completion.
Proposed independent slices need explicit ownership and integration obligations, not an automatic team
or aggregate terminal state. Each authorized slice retains profile, approval/lock, tests, accepted
VALID_RED and implementation order, its own scan root and honest scope/hold report. Held rows receive
no test or production edits. No slice's lock authorizes another's writes.

Detailed implementation decisions remain after VALID_RED. Changed source set or outcome requires
actual human confirmation/new revision, never expansion of an old lock. Re-read disk on resume.
REVIEW_VERIFIED is not deployed/operational success. Deployment, telemetry and rollback authority are
outside this adaptation. Return observed scope, reusable sources, proposed boundaries and open decisions.
Selected-profile specializations apply only at their current decision point.
