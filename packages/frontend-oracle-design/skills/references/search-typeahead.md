# 검색·자동완성 계약

입력에 따라 원격 결과를 갱신하는 UI(검색창, typeahead, combobox, 필터 검색,
mention picker)를 만들거나 바꾸기 전에 읽는다. 제출 버튼으로만 조회하는 폼,
클라이언트 메모리 내 필터링에는 적용하지 않는다.

이 문서는 정책을 만들지 않는다. **정책 후보 목록**과 **검증 의무**를 제공한다.
아래 표의 항목이 Oracle Card에 없으면 임의로 정하지 말고 `NEEDS_DECISION`으로
돌아간다. 구현 수단 선택은 [`frontend-implementation.md`](frontend-implementation.md)의
권위 순서를 따른다.

## 1. 카드에 잠글 정책

| 정책           | 물어야 할 것                                                       | 미결일 때        |
| -------------- | ------------------------------------------------------------------ | ---------------- |
| 조회 시작 조건 | 최소 글자 수. 공백만 입력일 때 동작                                | `NEEDS_DECISION` |
| 입력 대기      | debounce 시간. 붙여넣기·지우기도 같은 대기를 적용하는가            | `NEEDS_DECISION` |
| 빈 쿼리        | 입력을 전부 지우면 결과를 비우는가 최근 결과를 유지하는가          | `NEEDS_DECISION` |
| 이전 결과 유지 | 새 쿼리 로딩 중 이전 결과를 남기는가 비우는가                      | `NEEDS_DECISION` |
| 결과 없음      | `결과 없음`과 `조회 전` UI가 구분되는가                            | `NEEDS_DECISION` |
| 오류           | 오류 시 이전 결과를 유지하는가. 재시도가 자동인가 사용자 액션인가  | `NEEDS_DECISION` |
| 정규화         | 대소문자·앞뒤 공백·중복 공백·유니코드 정규화 후 같은 쿼리로 보는가 | `NEEDS_DECISION` |
| IME 조합       | 한글·일본어 조합 중 입력에도 조회하는가 확정 후에만 하는가         | `NEEDS_DECISION` |
| 캐시           | 같은 쿼리 재입력 시 캐시를 쓰는가. 신선도 기준은 무엇인가          | `NEEDS_DECISION` |
| 선택 확정      | 항목 선택 시 입력값·목록·포커스·라우팅이 어떻게 되는가             | `NEEDS_DECISION` |
| 히스토리       | 최근 검색어를 저장하는가. 저장 위치와 삭제 수단                    | `NEEDS_DECISION` |

**IME 조합 정책은 한국어 제품에서 생략 금지다.** 조합 중 `input` 이벤트는 자모
단위로 발생하므로 정책 없이 구현하면 `ㅎ`, `하`, `한`이 각각 조회된다. 조합 중
조회 여부는 결과를 바꾸는 정책이므로 카드에 잠근다.

## 2. 구현 기본값

정책이 잠긴 뒤에만 적용한다.

| 결정      | 기본값                                                    | 벗어나는 조건                              |
| --------- | --------------------------------------------------------- | ------------------------------------------ |
| 입력 대기 | debounce (입력이 멈춘 뒤 1회)                             | 연속 신호(scroll·resize)에만 throttle      |
| 요청 취소 | `queryFn`의 `AbortSignal`을 실제 요청에 전달              | 취소가 계약이 아니면 최신 응답만 채택      |
| 데이터    | 쿼리를 query key에 넣고 cache가 소유                      | effect에서 수동 `refetch` 금지             |
| 이전 결과 | 유지가 정책이면 `placeholderData`, 비우기면 명시적 초기화 | 카드 정책과 반대로 구현하지 않는다         |
| 마크업    | W3C ARIA APG Combobox 패턴                                | 레포에 승인된 combobox 프리미티브가 있으면 |
| 키보드    | 위/아래 이동, Enter 확정, Esc 닫기, 활성 항목 스크롤      | —                                          |

- 쿼리는 정규화 **후** 값을 query key에 넣는다. 정규화 전 원문을 key로 쓰면 `사과 `와
  `사과`가 다른 캐시 항목이 된다.
- 조합 중 조회하지 않는 정책이면 `compositionstart`/`compositionend`로 판정한다.
  `keyCode 229` 같은 브라우저별 우회에 의존하지 않는다.
- debounce 타이머를 컴포넌트 밖 모듈 스코프에 두지 않는다. 인스턴스가 둘이면 서로
  타이머를 덮어쓴다.
- 목록을 `role="listbox"`로 만들면 활성 항목을 `aria-activedescendant`로 연결하고
  포커스는 입력에 남긴다.

## 3. 결정론적으로 검증할 것

테스트는 sibling `test` skill 계약을 따르고 network 경계는 MSW handler로 세운다.
아래는 카드 행에 매핑해야 하는 최소 관찰이다.

- **응답 순서 역전**: `사과` 응답이 `사과나무` 응답보다 늦게 도착해도 최신 쿼리 결과만
  남는지 확인한다. 이 검증 없이 검색 구현을 GREEN으로 판정하지 않는다.
- **debounce 경계**: 대기 시간 안에 연속 입력하면 요청이 1회인지 요청 **총 횟수**로
  확인한다. 가짜 타이머로 경계 직전·직후를 모두 본다.
- **최소 글자 수 미만**: 요청이 아예 발생하지 않는지 확인한다.
- **IME 조합**: 정책이 `확정 후 조회`면 조합 중 입력에서 요청이 0회인지 확인한다.
- **빈 쿼리 복귀**: 전부 지웠을 때 카드 정책대로 결과가 비거나 유지되는지 확인한다.
- **오류 후 재입력**: 오류 상태에서 새 쿼리를 입력하면 복구되는지 확인한다.
- **키보드 확정**: 마우스 클릭과 Enter 확정이 같은 결과를 만드는지 확인한다.

임의 sleep으로 GREEN을 만들지 않는다. 대기는 관찰 가능한 상태 변화에 건다.

## 4. 배치

FSD 레포는 [`fsd.md`](fsd.md)를 따른다.

| 요소                                        | 위치                     |
| ------------------------------------------- | ------------------------ |
| 검색 요청 함수·DTO 변환                     | `<slice>/api`            |
| query key·검색 query options·히스토리 store | `<slice>/model`          |
| 입력·목록 component·키보드 처리             | `<slice>/ui`             |
| 쿼리 정규화·하이라이트 순수 함수            | `<slice>/lib`            |
| MSW handler와 결과 fixture                  | `<slice>/api/__mocks__/` |

## 5. 자주 나오는 위반

| 위반                                         | 교정                                                |
| -------------------------------------------- | --------------------------------------------------- |
| IME 조합 중 자모 단위로 조회                 | 조합 정책을 카드에 잠그고 composition 이벤트로 판정 |
| 순서 역전 검증 없이 검색 완료 처리           | 최신 쿼리 결과만 남는 결정론 테스트 추가            |
| 정규화 전 원문을 query key로 사용            | 정규화 후 값을 key로 사용                           |
| effect에서 입력 변화를 수동 `refetch`로 추종 | 쿼리를 query key에 포함                             |
| debounce 타이머를 모듈 스코프에 보관         | 인스턴스별 타이머로 이동                            |
| 결과 목록을 `div` 나열로 구현                | ARIA Combobox 패턴과 키보드 이동 구현               |
| `결과 없음`과 `조회 전`을 같은 UI로 처리     | 카드에서 두 상태를 분리해 확인                      |
