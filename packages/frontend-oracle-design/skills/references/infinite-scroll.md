# 무한 스크롤·점진 목록 계약

목록을 나눠서 이어 붙이는 UI(무한 스크롤, `더 보기`, 커서 피드, 무한 테이블)를
만들거나 바꾸기 전에 읽는다. 한 번에 전부 받는 목록, 고정 페이지네이션(1·2·3 번호
이동)에는 적용하지 않는다.

이 문서는 정책을 만들지 않는다. **정책 후보 목록**과 **검증 의무**를 제공한다.
아래 표의 항목이 Oracle Card에 없으면 임의로 정하지 말고 `NEEDS_DECISION`으로
돌아간다. 구현 수단 선택은 [`frontend-implementation.md`](frontend-implementation.md)의
권위 순서를 따른다.

## 1. 카드에 잠글 정책

| 정책           | 물어야 할 것                                                   | 미결일 때        |
| -------------- | -------------------------------------------------------------- | ---------------- |
| 페이지 경계    | cursor인가 offset인가. 서버가 실제로 무엇을 지원하는가         | `NEEDS_DECISION` |
| 페이지 크기    | 첫 페이지와 이후 페이지 크기가 다른가                          | `NEEDS_DECISION` |
| 정렬 안정성    | 정렬 키에 tie가 있는가. tie-break 키가 있는가                  | `NEEDS_DECISION` |
| 목록 변동      | 로드 중 항목이 추가·삭제되면 중복/누락을 허용하는가            | `NEEDS_DECISION` |
| 끝 도달        | 마지막 페이지를 어떻게 판정하고 무엇을 보여주는가              | `NEEDS_DECISION` |
| 빈 결과        | 첫 페이지가 비었을 때 UI가 `끝 도달`과 다른가                  | `NEEDS_DECISION` |
| 부분 실패      | 3번째 페이지 실패 시 앞 페이지를 유지하는가 전체를 버리는가    | `NEEDS_DECISION` |
| 재시도         | 자동인가 사용자 액션인가. 자동이면 횟수와 간격                 | `NEEDS_DECISION` |
| 스크롤 복원    | 뒤로가기·상세 이탈 후 위치와 로드된 페이지를 복원하는가        | `NEEDS_DECISION` |
| 항목 변경 반영 | 목록 내 항목을 수정·삭제하면 로드된 페이지에 어떻게 반영하는가 | `NEEDS_DECISION` |

`cursor`가 서버 계약에 없는데 목록이 실시간으로 변하면 중복·누락은 **정책 결정
사항**이지 구현 버그가 아니다. offset으로 구현하고 넘어가지 않는다.

## 2. 구현 기본값

정책이 잠긴 뒤에만 적용한다.

| 결정        | 기본값                                     | 벗어나는 조건                                      |
| ----------- | ------------------------------------------ | -------------------------------------------------- |
| 로드 트리거 | 목록 끝 sentinel + `IntersectionObserver`  | 스크롤 위치 계산이 제품 계약일 때만 scroll handler |
| 데이터 소유 | TanStack Query `useInfiniteQuery`          | 페이지 상태를 `useState` 배열로 직접 누적 금지     |
| 중복 요청   | 진행 중 fetch 중 sentinel 재교차는 무시    | —                                                  |
| 가상화      | 동시 DOM 항목이 수백 단위로 늘면 도입 제안 | 임계값과 라이브러리는 승인 후 추가                 |
| 스크롤 복원 | 복원이 정책이면 캐시 유지 + 복원 지점 명시 | 복원이 정책이 아니면 구현하지 않는다               |

- sentinel은 마지막 항목 자체가 아니라 목록 뒤의 전용 요소에 붙인다. 항목에 붙이면
  가상화·항목 제거와 함께 observer가 사라진다.
- `getNextPageParam`이 `undefined`를 돌려주는 조건이 카드의 `끝 도달` 판정과 같은지
  확인한다. 빈 배열과 `hasNextPage: false`를 같은 것으로 가정하지 않는다.
- 로드 트리거를 effect에서 스크롤 값 비교로 만들지 않는다.
- 가상화를 성능 근거 없이 기본으로 넣지 않는다. 도입하면 키보드 이동, 포커스 유지,
  스크린 리더 항목 수 노출이 계약대로 남는지 함께 검증한다.

## 3. 결정론적으로 검증할 것

테스트는 sibling `test` skill 계약을 따르고 network 경계는 MSW handler로 세운다.
아래는 카드 행에 매핑해야 하는 최소 관찰이다.

- **중복 요청 차단**: sentinel이 연속 교차해도 같은 페이지 요청이 1회인지 요청
  **총 횟수**로 검증한다. 렌더 결과만 보지 않는다.
- **응답 순서 역전**: page 2 응답이 page 3보다 늦게 도착해도 목록 순서와 다음 커서가
  카드대로 남는지 확인한다.
- **중복 key**: 페이지 경계에서 같은 항목이 두 번 렌더되지 않는지 확인한다.
- **부분 실패 후 재시도**: 실패한 페이지만 다시 요청하고 앞 페이지가 카드 정책대로
  유지·폐기되는지 확인한다.
- **끝 도달**: 마지막 페이지 이후 추가 요청이 발생하지 않는지 요청 횟수로 확인한다.
- **스크롤 복원**이 정책이면 복원 경로를 브라우저 검증 행으로 잡는다. 단위 테스트로
  대체하지 않는다.

임의 sleep으로 GREEN을 만들지 않는다. 대기는 관찰 가능한 상태 변화에 건다.

## 4. 배치

FSD 레포는 [`fsd.md`](fsd.md)를 따른다.

| 요소                                 | 위치                     |
| ------------------------------------ | ------------------------ |
| 목록 요청 함수·DTO 변환              | `<slice>/api`            |
| query key·`useInfiniteQuery` options | `<slice>/model`          |
| 목록 component·sentinel·상태 UI      | `<slice>/ui`             |
| 페이지 병합·중복 제거 순수 함수      | `<slice>/lib`            |
| MSW handler와 페이지 fixture         | `<slice>/api/__mocks__/` |

## 5. 자주 나오는 위반

| 위반                                     | 교정                                             |
| ---------------------------------------- | ------------------------------------------------ |
| 페이지 배열을 `useState`로 누적          | query cache가 페이지를 소유하게 한다             |
| 마지막 항목에 observer 부착              | 목록 뒤 전용 sentinel로 이동                     |
| 진행 중 요청 중 재트리거 방치            | pending 동안 트리거를 무시하고 요청 횟수로 검증  |
| offset 페이지네이션으로 실시간 목록 구현 | 중복·누락 정책을 카드에 잠근 뒤 수단 선택        |
| 실패 시 전체 목록 초기화를 임의 결정     | 부분 실패 정책을 카드에서 확인                   |
| 근거 없이 가상화 도입                    | 임계값 근거와 접근성 재검증을 함께 제시하고 승인 |
| 렌더 결과만 보고 중복 요청 없다고 판정   | 요청 총 횟수 assertion 추가                      |
