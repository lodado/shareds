**Architecture**
- **TenantScope:** holds the active tenant plus an epoch counter that increases on every switch.
- **QueryKey:** `(tenantId, resource, params)`, with the tenant required and first.
- **QueryCache:** partitioned by tenant, so a tenant can be evicted as a whole.
- **Fetcher:** deduplicates identical in-flight reads and tags each request with its tenant and epoch.
- **Commit gate:** drops late or superseded responses instead of writing them to the cache.
- **View binding:** reads only the active tenant's entry.
- **PlaceholderProvider:** returns a tagged placeholder that is never cached as real data and never taken from another tenant.

**Proposed axes**
- **Data:** two tenants, empty/one/page/max volumes, fresh/stale/expired.
- **Async:** network, 401/403, 5xx and malformed-response errors.
- **Order:** response inversion, a late response after a tenant switch, a late response after unmount, and A→B→A switches.
- **Entry:** includes deep-link.
- **Environment:** StrictMode included.
- **Excluded:** viewport, theme, reduced-motion and Platform have no behavioral outcome yet.

**Open questions** (★ = recommended)
- **Q1: Tenant identity.** (a) Opaque id from the session or URL, with the server enforcing access ★. (b) Derived from user claims.
- **Q2: Placeholder source.** (a) Static shell derived from the key only ★. (b) Previous data of the same tenant. (c) Another tenant's data, which I recommend against because it conflicts with isolation.
- **Q3: Old tenant's cache on switch.** (a) Keep it in its own bounded partition ★. (b) Drop it at once.
- **Q4: Out-of-order responses.** (a) Latest-issued request wins ★. (b) First wins. (c) Forbid concurrent requests for the same key.
- **Q5: Query library.** (a) The repo's library, or TanStack-style semantics ★. (b) A bespoke cache. This is blocked until a repo stack exists.
- **Q6: Mutations and optimistic updates.** (a) Out of scope for this first plan ★. (b) In scope.
- **Q7: Error behavior.** (a) Keep the last good same-tenant data with an error banner, and retry only definitive failures ★. (b) Replace the data with the error.
- **Q8: Revocation.** (a) A 401/403 purges that tenant's cached data ★. (b) Keep it.
- **Q9: Invalidation while a request is in flight.** (a) Discard the in-flight result and refetch ★. (b) Let it commit, then refetch.
- **Q10: Persistence.** (a) Memory only ★. (b) localStorage or IndexedDB.
