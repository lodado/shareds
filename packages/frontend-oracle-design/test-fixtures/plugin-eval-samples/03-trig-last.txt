**What the plan covers**
- **Layers:** a tenant context with an epoch counter, a key factory that can't build a key without a tenant ID, a tenant-namespaced cache, an abortable fetcher, a pure state machine for the view, and a placeholder provider that marks its output as placeholder.
- **Six invariants:**
  - Rendered data always belongs to the active tenant.
  - Cache keys always include the tenant.
  - Only the latest response for the current tenant epoch is applied.
  - Placeholder data is never cached or treated as a success.
  - Tenant switch, logout and session expiry abort in-flight requests and clear or quarantine the old tenant's cache entries.
  - Identical concurrent requests are sent once.
- **State model and axes:** the view's states and events, plus about 13 proposed axes (cache state, placeholder source, error subtype, order inversion, tenant switch during a request, and so on). None are confirmed yet.
- **Verification plan:** what would be proven or tested once approved, and what falls outside the Oracle (visual styling, real network timing).
