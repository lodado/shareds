# UX checklist — Funnel → Impression → Interaction → Conversion → Retention

화면 단위가 아니라 **여정 단위**로 본다. 각 질문에 `evidence`(화면의 무엇이 근거인가)와
`improvement`(있다면 개선 후보 한 줄)를 적는다. 개선 후보 목록이 이 체크리스트의 산출물이다.

## Funnel — 여기까지 어떻게 오나

- [ ] 진입점이 발견 가능한가? 사용자가 이 화면에 오는 경로(nav · 검색 · 링크 · 딥링크)를 셀 수 있다.
- [ ] 지금 어디에 있는지 알 수 있는가? 제목 · breadcrumb · 활성 nav 중 하나 이상.
- [ ] 다음이 무엇인지 알 수 있는가? primary action이 다음 단계를 이름으로 말한다.
- [ ] 돌아가는 길이 있는가? back · 취소 · 닫기가 예측 가능한 곳으로 보낸다.
- [ ] 딥링크로 들어와도 맥락이 유지되는가? URL이 상태(탭 · 필터 · 페이지)를 담는다.

## Impression — 5초 안에

- [ ] 이것이 무엇인지 알 수 있다.
- [ ] 누구를 위한 것인지 알 수 있다.
- [ ] 무엇을 하면 되는지 알 수 있다(primary action이 보인다).
- [ ] 신뢰 신호가 진짜다(실제 수치 · 실제 로고 · 실제 후기). 없으면 없는 대로 둔다.
- [ ] 첫 화면이 로딩 중에도 형태가 있다(skeleton · 예약된 공간, CLS 없음).

## Interaction — task를 끝내는 동안

- [ ] primary task 완료까지 조작 수를 세었고, 더 줄일 수 없다.
- [ ] 인지 부하 세 종류를 나눠 봤다.
  - intrinsic(task 자체의 난이도): 줄일 수 없다. 단계로 나누거나 기본값으로 덜어 준다.
  - extraneous(화면이 만든 부하): 장식 · 불필요한 선택지 · 일관성 없는 이름. 전부 지운다.
  - germane(배우는 부하): 첫 사용에만 허용. 반복 사용자에겐 지름길로 대체.
- [ ] working memory: 한 번에 기억해야 할 항목이 4개를 넘지 않는다. 넘으면 화면에 남겨 둔다(요약 패널 · 진행 표시).
- [ ] 한 화면에 결정 요소가 7개를 넘지 않는다. 넘으면 그룹화 또는 단계 분리.
- [ ] 필요한 정보가 필요한 순간에 있다(가격은 결제 버튼 옆, 남은 횟수는 입력 옆).
- [ ] 실수가 복구 가능하다. undo · 편집 · 재시도 중 하나가 항상 있다.
- [ ] 기다리는 동안 무엇을 기다리는지 안다(진행 표시 · 예상 시간 · 취소).
- [ ] 스크롤 · 탭 · 모달 중 조작 모델이 task 구조와 맞다(비교 → 나란히, 순차 → 단계, 세부 → 모달).
- [ ] 키보드 · 스크린리더 · 320px에서도 같은 task를 끝낼 수 있다.
- [ ] 시스템 상태가 항상 보인다(저장됨 · 동기화 중 · 오프라인).

## Conversion — 끝내는 순간

- [ ] primary CTA가 하나이고, 화면 어디서든 도달 가능하다(긴 화면이면 sticky).
- [ ] CTA 직전의 마찰을 지웠다(불필요한 필수 필드 · 가입 강제 · 재확인).
- [ ] CTA 옆에 결과와 비용이 적혀 있다(무엇이 일어나는지, 얼마인지, 되돌릴 수 있는지).
- [ ] 실패 시 입력이 보존되고 이유와 다음 행동이 있다.
- [ ] 완료 후 다음 행동이 제시된다(빈 성공 화면 금지).

## Retention — 다시 오게 하기

- [ ] 돌아왔을 때 상태가 남아 있다(작성 중 · 필터 · 마지막 위치).
- [ ] 반복 사용자에게 지름길이 있다(최근 항목 · 단축키 · 기본값 기억).
- [ ] 알림 · 배지 · 이메일이 사용자 이득 기준이다. 수신 거부가 한 번에 된다.
- [ ] 변화가 보인다(새 항목 · 진행률 · 이력).
- [ ] 떠나는 길이 존중된다(삭제 · 해지 · 내보내기가 숨겨져 있지 않다).

## 산출물 형식

```md
## UX 개선 포인트 — <화면>

| 단계        | 발견                     | 근거              | 개선 후보                      | 심각도 |
| ----------- | ------------------------ | ----------------- | ------------------------------ | ------ |
| Interaction | 결제까지 조작 6회        | 주소 재입력 2단계 | 주소 자동완성 + 기본 주소 기억 | high   |
| Impression  | 첫 화면에 CTA 없음       | fold 아래 480px   | hero 안으로 CTA 이동           | high   |
| Retention   | 필터가 새로고침에 사라짐 | URL에 상태 없음   | query string 동기화            | medium |
```

심각도: `blocker` = primary task를 끝낼 수 없음, `high` = 완료를 늦추거나 오류 유발,
`medium` = 재방문 · 신뢰에 영향, `nit` = 그 외. `blocker`와 `high`는 이번 구현에 포함하고
나머지는 목록으로 전달한다.
